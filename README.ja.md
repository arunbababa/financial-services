## どう仕事を進める設計か

中心は「受け取る入力、分析手順、成果物、確認項目、人に戻す境界」を細かく決めた指示書です。たとえばPitch Agentは、対象企業と仮説から類似企業・類似取引を調べ、DCF/LBO等を作り、モデルと提案スライドにまとめます。GL Reconcilerは照合差異を抽出し、別の担当が原本で再確認して、承認用の例外レポートにします。

スキルは関連する仕事で参照される手順書、コマンドは明示的に呼び出す入口、エージェントは複数手順をまとめる役割です。Cowork/Claude Codeで使うプラグインと、Claude Managed Agents API用の雛形が同じ英語の指示・スキルを参照しています。子エージェントへの委任、読取担当と成果物作成担当の分離、出力先`./out/`、人による承認などの設計も含まれます。

「論点をどう構造化するか」全般を扱うコンサル研修というより、金融業務の成果物を一定の手順と品質基準で作るための具体的な作業標準です。日々の仕事に転用しやすいのは、根拠と仮定の分離、入力と成果物の定義、別担当による照合、品質チェック、承認条件、引継ぎを明文化する部分です。

## 読むことと実行すること

Forkやこの日本語文書を読むだけでは、エージェントの配備、外部接続の認証、Office設定変更は行われません。日本語ミラーは読解用で、インストール済みの日本語プラグインではありません。

実行する場合はClaude製品やAPI、各データプロバイダーの契約・認証、利用環境に合うツールが別途必要です。上流READMEはMCPに購読契約やAPIキーが必要な場合があると説明しています。Managed Agent配備スクリプトはスキルを外部APIにアップロードし、子・親エージェントを作成します。Microsoft 365導入手順にはクラウド資源の作成、管理者同意、ユーザー属性の書込みも含まれます。無料で完結する構成とは確認していません。

この作業ではプラグインのインストール、API配備、外部MCP接続、Office設定変更、上流スクリプトの実行を行っていません。利用時の権限・費用・安全性は実環境で別途確認する必要があります。

## 静的確認で見つかった上流の不整合

- `plugins/vertical-plugins/financial-analysis/.mcp.json`は、翻訳基準コミットの原本でJSON構文が不正です。`egnyte`後のカンマと末尾の閉じ括弧が不足しています。原本は修正していません。
- READMEは「11 connectors」と記載しますが、一覧にはBoxを含む12接続先があります。
- READMEの`claude-for-financial-advisors`へのリンク先ディレクトリは、このコミットに存在しません。S&P GlobalのREADMEにも、URLのスキームがなく相対パスとして解釈されるリンクが1件あります。原文由来の欠落として記録しています。
- `scripts/check.py`は検査前に`git config core.hooksPath .githooks`を設定します。単なる読取専用検査ではありません。フックはプラグインのバージョンを更新し得ます。
- Managed AgentのREADMEにはスキーマ検証の説明がありますが、配備コードは`output_schema`を送信前に削除します。`scripts/validate.py`を各出力へどう組み込むかは利用者側で確認が必要です。文書の説明を実行時の保証とは扱えません。
