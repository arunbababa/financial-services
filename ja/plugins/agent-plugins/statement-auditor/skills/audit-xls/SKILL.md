<a id="audit-spreadsheet"></a>
# スプレッドシートを監査する

式とデータの正確性と間違いを監査します。スコープは、選択項目の簡単な数式チェックから完全な財務モデルの整合性監査まで、深さを決定します。

<a id="step-1-determine-scope"></a>
## ステップ 1: 範囲を決定する

ユーザーがすでにスコープを指定している場合は、それを使用します。それ以外の場合は**彼らに尋ねてください**:

> どの範囲を監査してほしいですか?
> - **選択** — 現在選択されている範囲のみ
> - **シート** — 現在アクティブなシートのみ
> - **モデル** — 財務モデルの整合性チェック (BSの貸借一致、現金残高の照合、ロールフォワード、ロジック健全性) を含むワークブック全体

**モデル** の範囲は最も詳細で、クライアントまたは IC に送信する前に、DCF、LBO、財務三表、合併、類似企業比較、またはその他の統合財務モデルに使用します。

---

<a id="step-2-formula-level-checks-all-scopes"></a>
## ステップ 2: 式レベルのチェック (すべてのスコープ)

スコープに関係なくこれらを実行します。

| チェックする | 何を探すべきか |
|---|---|
| 数式エラー | `#REF!`, `#VALUE!`, `#N/A`, `#DIV/0!`, `#NAME?` |
| 数式内のハードコード | `=A1*1.05` — `1.05` はセル参照である必要があります |
| 一貫性のない数式 | 行/列内の隣接する数式のパターンを打ち破る数式 |
| オフバイワン範囲 | 最初または最後の行が欠落している `SUM`/`AVERAGE` |
| 上書きされた数式 | 数式のように見えますが、実際にはハードコードされた値であるセル |
| 循環参照 | 意図的または偶然 |
| シート間のリンクが壊れている | 移動または削除されたセルへの参照 |
| 単位とスケールの不一致 | 千と百万を混合、% は整数として保存 |
| 非表示の行/タブ | オーバーライドまたは古い計算が含まれる可能性があります |

<a id="step-3-model-integrity-checks-model-scope-only"></a>
## ステップ 3: モデルの整合性チェック (MODEL スコープのみ)

スコープが **モデル** の場合、モデル タイプ (DCF / LBO / 財務三表 / マージャー / 類似企業比較 / カスタム) を特定し、以下の適切な整合性チェックを実行します。

<a id="3a-structural-review"></a>
### 3a.構造見直し

| チェックする | 何を探すべきか |
|---|---|
| 入力/式の分離 | 入力は計算から明確に分離されていますか? |
| 色の規則 | 青 = 入力、黒 = 式、緑 = リンク — またはモデルが使用するものはすべて一貫して適用されますか? |
| タブフロー | 論理的な順序 (仮定 → IS → BS → CF → 評価)? |
| 日付ヘッダー | すべてのタブで一貫していますか? |
| 単位 | 一貫しているか（千単位／百万単位／実数）？ |

<a id="3b-balance-sheet"></a>
### 3b.貸借対照表

| チェックする | テスト |
|---|---|
| BSバランス | 総資産＝負債総額＋資本（各期） |
| REロールフォワード | 以前の RE + 純利益 − 配当 = 現在の RE |
| のれん・無形資産 | 買収前提の流れ（M&Aの場合） |

BS のバランスが取れていない場合は、**期間ごとのギャップを定量化し、どこで整合が崩れるか追跡**します。これを修正するまでは、他のことよりも優先します。

<a id="3c-cash-flow-statement"></a>
### 3c.キャッシュフロー計算書

| チェックする | テスト |
|---|---|
| 現金残高の照合 | CF期末キャッシュ = BSキャッシュ（毎期） |
| CF合計 | CFO + CFI + CFF = Δ 現金 |
| D&Aマッチ | CF の D&A = IS の D&A |
| 資本支出の一致 | CF の設備投資は BS の PP&E ロールフォワードと一致します |
| WC（運転資本）の変動 | 符号がBSの増減と一致するか (ΔAR、ΔAP、Δ在庫) |

<a id="3d-income-statement"></a>
### 3D。損益計算書

| チェックする | テスト |
|---|---|
| 収益の構築 | セグメント/製品詳細との関連 |
| 税金 | 税金費用 = 税引前利益 × 税率 (繰延税調整額を考慮) |
| 株式数 | 希薄化スケジュールとの関係（オプション、転換証券、自社株買い） |

<a id="3e-circular-references"></a>
### 3e.循環参照

- 利子→負債残高→現金→利息は、LBO/3-stmt モデルでは一般的な意図的な循環です。
- 意図的な場合: 反復トグルが存在し、機能することを確認します。
- 意図的でない場合: ループをトレースし、それを解除する方法をフラグします。

<a id="3f-logic--reasonableness"></a>
### 3f。論理性と合理性

| チェックする | 次の場合にフラグを立てる |
|---|---|
| 成長率 | 説明なしに売上成長率が100%を超える |
| 利益率 | 業界標準の外にある |
| 継続価値の比率 | TV > DCF EV の約 75% (黄旗) |
| ホッケースティック | 予測が後半の年度で非現実的に急増する |
| 複利効果 | EBITDAは10年目までに莫大な金額に膨らむ |
| エッジケース | モデルは0%またはマイナス成長、マイナスEBITDA、マイナスレバレッジで破綻する |

<a id="3g-model-type-specific-bugs"></a>
### 3g。モデルタイプ固有のバグ

**DCF:**
- 割引率が間違った期間に適用される（年度途中と年末）
- 継続価値が現在価値に割り引かれていない
- WACC は時価ではなく簿価を使用します
- FCFに支払利息が含まれている（アンレバードであるべき）
- 税金シールドの二重カウント

**LBO:**
- 債務返済額がキャッシュスイープ（余剰現金による返済）の仕組みと一致しない
- PIK利息が元本に加算されていない
- 経営陣の持分再投資（ロールオーバー）が投資リターンに反映されていない
- 間違ったEBITDAに適用されたExit Multiple (LTM vs NTM)
- 手数料/経費は実行初日の出資額から差し引かれません

**合併:**
- 増加/希薄化で間違った株式数が使用される (取引前と取引後)
- 相乗効果は段階的に導入されていない
- 購入価格の配分のバランスが取れていない
- 使用した現金により失われる受取利息が含まれていない
- 取引手数料は資金調達・使途表に含まれない

**3-statement:**
- 運転資本の変化の符号が間違っている
- 減価償却費がPP&Eスケジュールと一致しない
- 借金の満期スケジュールが元金の支払いと一致しない
- 説明もなく配当が純利益を上回る

<a id="step-4-report"></a>
## ステップ4：報告する

指摘事項を次の表で示します：

| # | シート | セル/範囲 | 重大度 | カテゴリ | 問題 | 提案される修正 |
|---|---|---|---|---|---|---|

**重大度:**
- **重大** — 間違った出力 (BS のバランスが取れていない、式が壊れている、現金残高が照合一致しない)
- **警告** — 危険です (ハードコード、一貫性のない式、エッジケースの障害)
- **情報** — スタイル/ベストプラクティス (色分け、レイアウト、命名)

**モデル** スコープの場合は、概要行を先頭に追加します。

> モデル タイプ: [DCF/LBO/3-stmt/...] — 全体: [クリーン / 軽微な問題 / 重大な問題] — [N] 重大、[N] 警告、[N] 情報

**質問なしに何も変更しないでください** - まず報告し、要求に応じて修正します。

<a id="notes"></a>
## 注意事項

- **BS のバランスが最初** — バランスが取れていない場合は、下流のすべてが疑わしいことになります
- **ハードコードされたオーバーライドはサイレント バグの最大の原因です** — 積極的に検索してください
- **符号規則の誤り** (現金流出のプラスとマイナス) は非常に一般的です。
- モデルで VBA マクロが使用されている場合は、数式だけでは監査できないマクロ駆動の計算に注意してください。
