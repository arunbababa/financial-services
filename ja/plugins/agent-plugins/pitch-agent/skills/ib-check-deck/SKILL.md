<a id="ib-deck-checker"></a>
# IBデッキチェッカー

プレゼンテーションに対して 4 つの側面にわたって包括的な QC を実行します。すべてのスライドを読み、結果を報告します。

<a id="environment-check"></a>
## 環境チェック

このスキルは、PowerPoint アドインとチャットの両方で機能します。開始する前に、自分がどちらにいるのかを確認してください。

- **アドイン** — ライブのオープンデッキから読み取ります。
- **チャット** — アップロードされた `.pptx` ファイルから読み取ります。

これは読み取りとレポートのみであり、編集は行われないため、ワークフローは両方で同じです。

<a id="workflow"></a>
## ワークフロー

<a id="read-the-deck"></a>
### デッキを読む

すべてのスライドからテキストを抽出し、各行がどのスライドから来たのかを追跡します。すべての結果に対してスライド レベルの帰属が必要になります (「スライド 3 と 8 には 5 億ドルと表示されますが、スライド 15 には 4 億 8,500 万ドルと表示されます」)。 30 枚のスライドを含むデッキは作業メモリに確実に保持するには多すぎます。番号チェック スクリプトが処理できるように、抽出したテキストをファイルに書き込みます。

このスクリプトは、スライド マーカーを使用したマークダウン風の入力を想定しています。次のようにフォーマットします:

```
## Slide 1
[slide 1 text content]

## Slide 2
[slide 2 text content]
```

<a id="1-number-consistency"></a>
### 1. 数値の一貫性

収集したものに対して抽出スクリプトを実行します。

```bash
python scripts/extract_numbers.py /tmp/deck_content.md --check
```

単位を正規化し ($500M 対 $500MM vs $500,000,000 → 同じ数値)、値を分類し (収益、EBITDA、倍数、利益率)、同じ指標カテゴリが異なるスライドで矛盾する値を示した場合にフラグを立てます。これは、人間が 5 回目の読み上げで見逃したものを見つける可能性が最も高い部分です。

スクリプトのフラグ以外にも、以下を確認してください。
- 計算は正しい (合計、パーセンテージの合計、成長率がエンドポイントと一致する)
- ユニットのスタイルは一貫しています - デッキは $M または $MM のいずれかを選択し、それを使用する必要があります
- 期間が調整されています - 会計年度、LTM、四半期、明示的にラベル付けされています

<a id="2-data-narrative-alignment"></a>
### 2. データとナラティブの調整

主張を、それを裏付けるデータに対応付けします。これは、デッキが静かに間違っているところです。誰かがスライド 7 の表を編集し、スライド 4 の説明を忘れてしまいます。

- トレンドに関する記述 (「利益率の低下」) → チャートは実際にその方向に進んでいますか?
- 市場での地位の主張 (「ナンバーワンプレーヤー」) → 収益とシェアのデータがそれを裏付けていますか?
- もっともらしさ — 売上高 2 億ドルの「1,000 億ドルの市場でナンバー 1」は 0.2% のシェアです。それは#1ではありません

<a id="3-language-polish"></a>
### 3. 言語を磨きます

IBデッキには固有の文体・言葉遣いがあります。カジュアルな表現 (「かなり良い」、「たくさんの」)、短縮形、感嘆符、数字のない曖昧な数量詞、同じ概念に対する一貫性のない用語など、それを破るものがないか調べてください。

置換パターンについては、`references/ib-terminology.md` を参照してください。

<a id="4-visual-and-formatting-qc"></a>
### 4. ビジュアルおよびフォーマットの QC

各スライドで標準の視覚的検証チェックを実行します。探しているのは、グラフのソース引用の欠落、軸ラベルの欠落、タイポグラフィーの不一致、数値書式のずれ (同じデッキ内で 1,000と1K)、日付形式のずれ、脚注と免責事項のギャップです。

視覚的な検証により、テキスト抽出では現れない重複、オーバーフロー、コントラストの問題が検出されます。読み飛ばさないでください。出典の引用がないグラフは、テキスト ダンプ内で適切に出典が記載されているグラフと同じように見えます。

<a id="output"></a>
## 出力

構造体として `references/report-format.md` を使用します。重大度別に分類します。

- **重大** — 数値の不一致、事実誤認、物語と矛盾するデータ。これらは顧客への提出を止めるします。
- **重要** — 言語、情報源の不足、用語のずれ。修正する必要があります。
- **マイナー** — フォント サイズ、間隔、日付形式。研磨。

重大な指摘から示します。何もない場合は、そのように明示的に言います。「数値の不一致は見つからなかった」という結果自体が一つの所見であり、所見がないことを意味するわけではありません。
