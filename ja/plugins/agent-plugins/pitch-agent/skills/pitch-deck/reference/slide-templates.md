# コンテンツ マッピングのリファレンス

このファイルは、ソース データをピッチデッキ テンプレート セクションにマッピングするためのガイダンスを提供します。このプロセスはテンプレートに依存しません。これらの原則は、特定のテンプレートの設計に関係なく適用されます。

<a id="template-analysis-process"></a>
## テンプレート分析プロセス

テンプレートを設定する前に、その構造を分析します。

<a id="step-1-identify-all-content-areas"></a>
### ステップ 1: すべてのコンテンツ領域を特定する

各スライドをスキャンして、次のことを確認します。
- **タイトル/ヘッダーのプレースホルダー** — スライドのタイトルが配置される場所
- **サブタイトル/定義領域** — 二次ヘッダーまたは定義
- **コンテンツ ボックス** — メイン コンテンツ領域 (ラベル サイドバーがある場合があります)
- **テーブル プレースホルダー** — 表形式のデータ用に指定された領域
- **チャート/ビジュアルエリア** — チャート、図、または画像用のスペース
- **指標コールアウト ボックス** — 強調表示された主要な数値
- **脚注/出典バー** — 引用と注記の下部領域
- **ロゴのプレースホルダー** — 通常は右上隅

<a id="step-2-note-template-conventions"></a>
### ステップ 2: 注記テンプレートの規則

各テンプレートには独自のスタイルがあります。観察してください:
- **配色** — ヘッダー、背景、アクセントにはどのような色が使用されますか?
- **フォントの選択** — どのようなフォントとサイズがすでに設定されていますか?
- **ボックスのスタイル** — コンテンツ ボックスにはサイドバー、境界線、または網掛けがありますか?
- **箇条書きスタイル** — テンプレートではどのような箇条書き記号が使用されますか?
- **配置パターン** — 平行セクションはどのように配置されますか?

<a id="step-3-identify-instruction-vs-output-areas"></a>
### ステップ 3: 命令と出力領域を特定する

テンプレートには多くの場合、次のようなガイダンスが含まれています。
- **説明ボックス** — 説明テキストが記載された色付きのボックス (多くの場合、背景が黄色、テキストが白)
- **プレースホルダー テキスト** — 置換対象を示す [括弧] 内のテキスト
- **コンテンツの例** — 予想される形式を示すサンプルコンテンツ

**主な違い**: 指示ボックスは何をすべきかを示します。最終出力では再フォーマットするか削除する必要があります。出力領域はコンテンツが置かれる場所です。

<a id="content-mapping-workflow"></a>
## コンテンツマッピングのワークフロー

<a id="step-1-inventory-source-data"></a>
### ステップ 1: ソース データのインベントリ

利用可能なすべてのデータのリストを作成します。
- 市場規模の数値と範囲
- 成長率 (CAGR、前年比)
- 会社名と説明
- セグメントの定義
- 財務指標
- 出典の引用と日付
- 脚注の内容

<a id="step-2-match-data-to-template-sections"></a>
### ステップ 2: データをテンプレート セクションに一致させる

各テンプレート セクションについて、以下を特定します。

| テンプレートセクション | 必要なデータ | ソースの場所 |
|------------------|---------------|-----------------|
| [セクション名] | 【必要なデータ】 | 【どこで見つけられるか】 |

<a id="step-3-identify-gaps"></a>
### ステップ 3: ギャップを特定する

マッピング後、次の点に注意してください。
- **データがありません** — テンプレートにはソースにないデータが必要です
- **追加データ** — ソースにはテンプレート ホームのないデータが含まれています
- **形式の不一致** — データは存在しますが、形式が間違っています

<a id="step-4-resolve-gaps-before-populating"></a>
### ステップ 4: データを入力する前にギャップを解決する

- データが欠落しています: ユーザーにフラグを立てるか、追加のソースを検索します
- 余分なデータ: 除外する必要があるかどうか、またはテンプレートの調整が必要かどうかを確認します。
- 形式の不一致: データを必要な形式に変換します

<a id="common-slide-types-and-data-requirements"></a>
## 一般的なスライドの種類とデータ要件

これらは、一般的なスライド タイプの典型的なデータ要件です。特定のテンプレートは異なる場合があります。常にテンプレートの実際の構造に従ってください。

<a id="market-definition-slides"></a>
### 市場定義スライド

**典型的なコンテンツ領域:**
- 範囲に含まれるセグメント (例/主要企業を含む)
- 範囲から除外されるセグメント (例付き)
- 市場定義テキスト
- 範囲の根拠/正当化

**データ マッピングに関する考慮事項:**
- ソース データは、含まれるセグメントと除外されるセグメントを明確に区別する必要があります
- 主要なプレーヤーはそれぞれのセグメントにマッピングされる必要があります
- 定義テキストは、ソースが市場を定義する方法と一致している必要があります

**通常必要なデータ:**
- 含める市場セグメントのリスト (主要企業の例を含む)
- 除外する市場セグメントのリスト (例付き)
- 市場定義テキスト
- 範囲の根拠または正当化

**書式設定の原則:** 並列セクション (含まれるセクションと除外されるセクション) では、一致する書式設定を使用する必要があります。

**確認の質問:**
- すべてのセグメントに適切な記号 (含まれる場合は ✓、除外される場合は ×) が付いていますか?
- キープレーヤーはセグメントに正しく割り当てられていますか?
- 定義はソースの方法論と一致していますか?

<a id="market-sizing--tam-slides"></a>
### 市場規模/TAM スライド

**典型的なコンテンツ領域:**
- 現在の市場規模（年とともに）
- 成長率 (期間付き CAGR)
- 将来予測（目標年度あり）
- ソースごとの内訳表
- コンセンサス/集計値
- 重要なポイントや洞察

**通常必要なデータ:**
- 基準年との市場規模の数値
- 成長率 (期間に応じた CAGR)
- 目標年度との予測数値
- 各データポイントの出典引用

**列ヘッダーの例:** ソース | [基準年] サイズ | CAGR | 【目標年度】 見通し

**書式設定の原則:** 複数のソースを表示する場合は、コンセンサス/要約行を含めます。

**データ マッピングに関する考慮事項:**
- 複数のソースが異なる推定値を持つ場合があります。それぞれをテーブルの行にマッピングします
- コンセンサス数値は個別の情報源から計算する必要がある
- 予測は CAGR 式を使用して検証可能である必要があります

**確認の質問:**
- すべての出典の数値は元の文書と一致していますか?
- コンセンサスは正しく計算されていますか (1 つのソースからコピーしただけではありません)?
- 予測年はすべての数値で一貫していますか?
- 手動で検証した場合、CAGR ベースの予測は一致しますか?

<a id="competitive-landscape-slides"></a>
### 競争環境のスライド

**典型的なコンテンツ領域:**
- 競合他社を列にした比較表
- 機能/能力の行
- 財務指標行 (収益、成長、市場シェア)
- 主な所見または位置付けに関するメモ

**通常必要なデータ:**
- 比較する競合他社のリスト
- それぞれの機能または機能
- 財務指標 (収益、成長、市場シェア) (可能な場合)
- 財務データの期間

**書式設定の原則:** 対象会社は競合他社と視覚的に区別できるようにする必要があります (例: 太字のテキスト、異なる背景色、境界線、または右端の列に配置する)。

**データ マッピングに関する考慮事項:**
- ソース データの競合他社がすべて含まれていることを確認する
- 機能の比較には一貫した基準を使用する必要があります
- 財務数値は比較可能な期間のものである必要があります

**確認の質問:**
- ソース データの競合他社はすべて表されていますか?
- 対象企業は視覚的に区別できますか?
- 財務数値は同じ期間のものですか?
- ✓/× の使用法は一貫していて正確ですか?

<a id="financial-summary-slides"></a>
### 財務概要スライド

**典型的なコンテンツ領域:**
- 主要な指標のコールアウト (見出しの数字)
- 過去の財務表（実績）
- 予想財務表（予想）
- 成長率と利益率
- オプションのトレンドチャート

**通常必要なデータ:**
- 近年の財務実績（実績）
- 将来の財務予測（推定）
- 主要な指標: 収益、成長率、利益率、EBITDA

**列ヘッダーの例:** メトリック | FY[Year-2] | FY[Year-1] | 年度[年]A | 年度[年+1]E | 年度[年+2]E

**フォーマットの原則:** 過去のデータ (A) と予測されたデータ (E) を明確に区別します。

**データ マッピングに関する考慮事項:**
- 過去のデータ (A) と予測されたデータ (E) を明確に区別する
- 指標の定義がソースと一致していることを確認します (収益と純収益、EBITDA と調整後 EBITDA)
- 成長率は一貫して計算する必要があります

**確認の質問:**
- 過去の期間と予測された期間は明確にラベル付けされていますか?
- 計算された成長率はソースまたは手動計算と一致しますか?
- メトリクスの定義はソース文書と一致していますか?

<a id="transaction-comparables-slides"></a>
### 取引比較スライド

**典型的なコンテンツ領域:**
- 取引テーブル (日付、ターゲット、買収者、取引金額)
- 評価倍率（EV/収益、EV/EBITDA）
- 要約統計量 (平均、中央値、高値、低値)
- 倍率から算出される対象企業の評価額

**通常必要なデータ:**
- 取引の詳細: 日付、ターゲット、買収者、取引額
- 評価倍率: EV/収益、EV/EBITDA
- 評価額を算出するための対象企業の指標

**書式設定の原則:** 倍率についての要約統計 (平均、中央値、高、低) を含めます。

**データ マッピングに関する考慮事項:**
- マルチプルは単にコピーするのではなく、トランザクション データから計算する必要があります
- 要約統計はすべてのトランザクションにわたって計算する必要があります
- 倍率から算出した評価額は対象企業の指標に倍数を適用します

**確認の質問:**
- ソースからのすべての関連トランザクションが含まれていますか?
- 倍数は正しく計算されていますか (EV ÷ メトリック)?
- 要約統計はテーブル内のすべてのトランザクションをカバーしていますか?
- 倍率から算出した評価額は例示として明確にラベル付けされていますか?

<a id="mapping-verification-checklist"></a>
## マッピング検証チェックリスト

フォーマットに移る前に、マッピングが完全であることを確認してください。

<a id="data-completeness"></a>
### データの完全性
- [ ] すべてのテンプレート プレースホルダーにはソース データがマッピングされています
- [ ] すべての情報源の引用は脚注に記録されます
- [ ] マップされていないプレースホルダー [括弧] はありません

<a id="data-accuracy"></a>
### データの精度
- [ ] 数値は元のソース文書と正確に一致します
- [ ] 年と期間が正しく記録されている
- [ ] 会社名の綴りが正しい
- [ ] 計算値（コンセンサス、予測、倍数）の検証

<a id="logical-consistency"></a>
### 論理的な一貫性
- [ ] 含まれるセグメントと除外されるセグメントは論理的に一貫しています
- [ ] 過去のデータは時系列的に予測データに先行します
- [ ] 比較データは一貫した期間を使用します
- [ ] 合計と小計が正しく合計される

<a id="source-attribution"></a>
### 出典の帰属
- [ ] すべてのデータポイントをソースまで追跡できます
- [ ] 出典名と出版年を記録
- [ ] 特別な注記に割り当てられた脚注番号

<a id="handling-data-template-mismatches"></a>
## データテンプレートの不一致の処理

<a id="template-requires-more-data-than-available"></a>
### テンプレートには利用可能なデータよりも多くのデータが必要です

**オプション:**
1. ユーザーレビューのためにギャップに明示的にフラグを立てます
2. セクションに説明を付けて「データが利用できません」とマークします
3. 必要に応じて追加のソースを検索します
4. データが存在しない場合はテンプレートの調整を推奨します

**禁止事項:** データを捏造したり、裏付けのない推定をしたりすること。

<a id="source-has-more-data-than-template-accommodates"></a>
### ソースにはテンプレートが収容できるよりも多くのデータが含まれています

**オプション:**
1. 最も関連性の高い最新のデータ ポイントを含める
2. 必要に応じて要約または集約する
3. 追加の利用可能なデータを参照する脚注を追加します
4. データが重要な場合はテンプレートの拡張を推奨します

<a id="data-format-doesnt-match-template-format"></a>
### データ形式がテンプレート形式と一致しません

**一般的な変換:**
- 個々の数値 → 範囲 (ソースからの最小値と最大値を使用)
- 詳細内訳→概要カテゴリ
- 年間数値 → CAGR (エンドポイントから計算)
- 絶対値→パーセンテージ（シェアを計算）
- 複数のソース → コンセンサス (方法論の適用)

<a id="template-uses-different-terminology"></a>
### テンプレートでは異なる用語が使用されています

**解決プロセス:**
1. テンプレート用語とソース用語を特定する
2. それらが同じ概念を指していることを確認する
3. 出力でテンプレート用語を使用する
4. 説明が必要な場合は脚注を追加してください

<a id="template-specific-adaptation"></a>
## テンプレート固有の適応

留意してください: このガイダンスでは、要件ではなく、一般的なパターンについて説明します。常に:

1. **テンプレートに従う** — テンプレートで異なるセクション名が使用されている場合は、それらのセクション名を使用してください
2. **テンプレート スタイルに一致する** - テンプレートの既存のフォント、色、箇条書きスタイルを使用します
3. **テンプレート構造を保持** - 必要な場合を除き、セクションを再配置しないでください。
4. **テンプレートの間隔を尊重する** — コンテンツはオーバーフローせずに指定された領域に収まる必要があります

目標は、テンプレートを再設計することではなく、設計どおりに設定することです。
