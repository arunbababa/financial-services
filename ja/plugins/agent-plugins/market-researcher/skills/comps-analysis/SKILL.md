# 類似会社分析

<a id="-critical-data-source-priority-read-first"></a>
## ⚠️ クリティカル: データソースの優先順位 (最初に読んでください)

**常に次のデータ ソース階層に従ってください:**

1. **最初: MCP データ ソースを確認します** - S&P Kensho MCP、FactSet MCP、または Daloopa MCP が利用可能な場合は、財務情報・取引情報には、それらのデータソースだけを使用してください。
2. 上記の MCP データ ソースが利用可能な場合は、**Web 検索を使用しないでください**
3. **MCP が利用できない場合のみ:** その場合は、ブルームバーグ ターミナル、SEC EDGAR 提出書類、またはその他の機関情報源を使用します。
4. **Web 検索を主要なデータ ソースとして決して使用しないでください** - Web 検索には、機関レベルの分析に必要な精度、監査証跡、信頼性が欠けています。

**これが重要な理由:** MCP ソースは、適切な引用とともに、検証済みの機関レベルのデータを提供します。 Web 検索結果は、財務分析としては古い、不正確、または信頼できない場合があります。

<a id="overview"></a>
## 概要
このスキルにより、Claude は、経営指標、評価倍率、統計的ベンチマークを組み合わせた機関レベルの比較可能な企業分析を構築することができます。出力は構造化された Excel/スプレッドシートであり、ピア比較を通じて情報に基づいた投資決定を可能にします。

**参考資料とコンテキスト化:**

比較対象企業分析の例は、`examples/comps_example.xlsx` に記載されています。このスキル ディレクトリ内のこのファイルまたは他のサンプル ファイルを使用する場合は、それらを賢く使用してください。

**次の目的で例を利用してください:**
- 構造階層の理解 (セクションの流れ)
- 期待される厳密さのレベルの把握 (統計の深さ、文書化の基準)
- 学習原則 (明確なヘッダー、透明な数式、監査証跡)

**次の目的で例を利用しないでください**
- フォーマットやメトリクスの正確な再現
- コンテキストを考慮せずにレイアウトをコピーする
- 視聴者に関係なく同じビジュアルスタイルを適用する

**常に最初に自分自身に問いかけてください:**
1. **「好みの形式はありますか、それともテンプレートのスタイルを適用する必要がありますか?」**
2. **「聴衆は誰ですか?」** (投資委員会、取締役会のプレゼンテーション、クイックリファレンス、詳細メモ)
3. **「重要な質問は何ですか?」** (評価、成長分析、競争上のポジショニング、効率)
4. **「その背景は何ですか?」** (M&A の評価、投資決定、セクターのベンチマーク、パフォーマンスのレビュー)

**詳細に基づいて調整します:**
- **業界の背景**: 大手テクノロジー企業には、新興の SaaS スタートアップとは異なる指標が必要です
- **セクター固有のニーズ**: 関連する指標を早期に追加します (例: クラウド ARR、企業顧客、テクノロジーの開発者エコシステム)
- **企業への精通度**: よく知られた企業では、背景説明を減らし、変化の分析に重点を置けます。
- **意思決定タイプ**: M&A には、継続的なポートフォリオのモニタリングとは異なる重点が必要です

**中心原則:** テンプレート原則 (明確な構造、統計的厳密性、透明性のある式) を使用しますが、コンテキストに基づいて実行を変更します。目標は、機関向けの品質の分析であり、機関向けのテンプレートを作成することではありません。

ユーザーが提供した例と明示的な設定は、常にデフォルトよりも優先されます。

<a id="core-philosophy"></a>
## 基本理念
**「まず適切な構造を構築してから、データにストーリーを語らせてください。」**

何が重要なのかについて戦略的思考を強制するヘッダーから始めて、クリーンなデータを入力し、透明性の高い数式を構築し、統計を自動的に表示させます。優れたコンプは、それを作成した人以外でもすぐに読めるようにする必要があります。

<a id="-critical-formulas-over-hardcodes--step-by-step-verification"></a>
## ⚠️ 重要: ハードコードよりも数式 + 段階的な検証

**環境 — Office JS と Python:**
- **Excel 内で実行している場合 (Office アドイン / Office JS):** Office JS を直接使用します (`Excel.run(async (context) => {...})`)。数式は、`range.values` ではなく、`range.formulas = [["=E7/C7"]]` 経由で記述します。別個の再計算手順はありません。Excel がネイティブに処理します。色/フォントには `range.format.*` を使用します。
- **スタンドアロンの .xlsx ファイルを生成する場合:** Python/openpyxl を使用します。 `cell.value = "=E7/C7"` (式文字列) を書き込みます。
- どちらの方法でも原則は同じです。API 呼び出しを変換するだけです。
- **Office JS マージ セルの落とし穴:** `.merge()` を呼び出してから、マージされた範囲に `.values` を設定しないでください (`InvalidArgument` がスローされます。範囲は依然としてマージ前のサイズを報告します)。代わりに、左上のセルのみに値を書き込み、全範囲を結合して書式設定します。
  ```js
  ws.getRange("A1").values = [["TECHNOLOGY — COMPARABLE COMPANY ANALYSIS"]];
  const hdr = ws.getRange("A1:H1");
  hdr.merge();
  hdr.format.fill.color = "#1F4E79";
  hdr.format.font.color = "#FFFFFF";
  hdr.format.font.bold = true;
  ```

**ハードコードではなく数式:**
- すべての派生値 (マージン、倍数、統計) は、入力セルを参照する Excel の数式である必要があります。事前に計算された数値を貼り付けることはできません。
- Python/openpyxl を使用してシートを構築する場合: `cell.value = 0.687` (計算結果) ではなく、`cell.value = "=E7/C7"` (式文字列) を書き込みます。
- ハードコードされた値のみが生の入力データ (収益、EBITDA、株価など) である必要があります。また、それらの値にはそれぞれソースを示すセル コメントが付けられます。
- 理由: 入力が変更されると、モデルは自動的に更新される必要があります。ハードコーディングされたマージンは、発生を待っている静かなバグです。

**ユーザーと一緒に段階的に確認します:**
- 構造を設定した後 → データを入力する前にヘッダー レイアウトをユーザーに表示する
- 生の入力を入力した後 → ユーザーに入力ブロックを表示し、数式を作成する前にソース/期間を確認します。
- 事業指標の式を構築した後 → 計算されたマージンを表示し、評価に進む前にユーザーに健全性を確認します。
- 評価倍率を構築した後 → 統計を追加する前に倍率を表示し、妥当であることを確認します
- シート全体を端から端まで作成してから提示しないでください。各セクションを確認してエラーを早期に発見してください。

<a id="section-1-document-structure--setup"></a>
## セクション 1: ドキュメントの構造と設定

<a id="header-block-rows-1-3"></a>
### ヘッダー ブロック (行 1 ～ 3)
```
Row 1: [ANALYSIS TITLE] - COMPARABLE COMPANY ANALYSIS
Row 2: [List of Companies with Tickers] • [Company 1 (TICK1)] • [Company 2 (TICK2)] • [Company 3 (TICK3)]
Row 3: As of [Period] | All figures in [USD Millions/Billions] except per-share amounts and ratios
```

**これが重要な理由:** すぐにコンテキストを確立します。このファイルを開いた人は、自分が何を見ているのか、いつ作成されたのか、そして数値をどのように解釈すればよいのかを知っています。

<a id="visual-convention-standards-optional---user-preferences-and-uploaded-templates-always-override"></a>
### ビジュアル規約標準 (オプション - ユーザー設定とアップロードされたテンプレートを常に優先します)

**重要: これらは推奨されるデフォルトのみです。常に優先順位を付ける:**
1. ユーザーの明示的な書式設定
2. アップロードされたテンプレート ファイルからのフォーマット
3. 会社/チームのスタイルガイド
4. これらのデフォルト (他にガイダンスが提供されていない場合のみ)

**推奨されるフォントとタイポグラフィ:**
- **フォント ファミリー**: Times New Roman (プロフェッショナルで読みやすい、業界標準)
- **フォント サイズ**: データ セルの場合は 11 ポイント、ヘッダーの場合は 12 ポイント
- **太字**: セクションヘッダー、会社名、統計ラベル

**デフォルトのカラーとシェーディング — プロフェッショナル ブルー/グレー パレット (最小限の方が良い):**
- **控えめにしてください** - ブルーとグレーのみ。緑、オレンジ、赤、または複数のアクセントカラーを導入しないでください。きれいな類似企業比較表には合計 3 ～ 4 色が使用されます。
- **セクションヘッダー** (例: 「事業統計と財務指標」):
  - ダークブルーの背景 (`#1F4E79` または `#17365D` ネイビー)
  - 白い太字のテキスト
  - すべての列にわたる完全な行シェーディング
- **列ヘッダー** (例: 「会社」、「収益」、「マージン」):
  - 水色の背景 (`#D9E1F2` または同様の淡い青)
  - 黒の太字テキスト
  - 中央揃え
- **データ行**:
  - 会社データの白い背景
  - 数式の場合は黒のテキスト。ハードコードされた入力の青いテキスト
- **統計行** (最大値、75 パーセンタイルなど):
  - ライトグレーの背景 (`#F2F2F2`)
  - 黒のテキスト、左揃えのラベル
- **これがパレット全体です**: ダークブルー + ライトブルー + ライトグレー + ホワイト。ユーザーのテンプレートに別途記載がない限り、他には何もありません。

**推奨される書式設定規則:**
- **小数精度**:
  - パーセンテージ: 小数第 1 位 (12.3%)
  - 倍数: 小数点 1 (13.5x)
  - ドル金額: 小数点なし、桁区切り記号 (69,632)
  - パーセンテージで表示されるマージン: 小数点第 1 位 (68.7%)
- **境界線**: 境界線なし (すっきりとした最小限の外観)
- **配置**: すべてのメトリクスが中央に配置され、すっきりとした均一な外観になります。
- **セルの寸法**: すべての列の幅は均一/均等である必要があり、すべての行の高さは一貫している必要があります (きれいで本格的なグリッドを作成します)

**注意:** ユーザーがテンプレート ファイルを提供するか、別の形式を指定する場合は、代わりにそれを使用してください。

<a id="section-2-operating-statistics--financial-metrics"></a>
## セクション 2: 営業統計と財務指標

<a id="core-columns-start-with-these"></a>
### コアカラム（まずはこれから）
1. **会社** - 一貫した形式の名前
2. **収益** - サイズ指標 (コンテキストに応じて LTM、四半期、または年次にすることができます)
3. **収益の伸び** - 前年比の変化率
4. **粗利益** - 収益から売上原価を差し引いたもの
5. **売上総利益率** - GP/収益 (基本的な収益性)
6. **EBITDA** - 利息、税金、減価償却費、償却前利益
7. **EBITDA マージン** - EBITDA/収益 (営業効率)

<a id="optional-additions-choose-based-on-industrypurpose"></a>
### オプション追加（業種・用途に応じて選択）
- **四半期と LTM** - 季節性が重要な場合は両方を含めます
- **フリー キャッシュ フロー** - 資本集約型または SaaS ビジネス向け
- **FCF マージン** - FCF/収益 (現金生成効率)
- **純利益** - 成熟した収益性の高い企業向け
- **営業利益** - さまざまな D&A を伴う企業向け
- **CapEx メトリクス** - 資産を多用する業界向け
- **40 のルール** - 特に SaaS (成長率 % + 利益率 %)
- **FCF転換率** - 収益の質の分析用 (上級)

<a id="formula-examples-using-row-7-as-example"></a>
### 式の例 (行 7 を例として使用)
```excel
// Core ratios - these are always calculated
Gross Margin (F7): =E7/C7
EBITDA Margin (H7): =G7/C7

// Optional ratios - include if relevant
FCF Margin: =[FCF]/[Revenue]
Net Margin: =[Net Income]/[Revenue]
Rule of 40: =[Growth %]+[FCF Margin %]
```

**黄金律:** すべての比率は [何か] / [収益] または [何か] / [このシートの何か] である必要があります。シンプルにしてください。

<a id="statistics-block-after-company-data"></a>
### 統計ブロック（企業データ後）

**重要: すべての比較可能な指標 (比率、マージン、成長率、倍数) の統計式を追加します。**

```
[Leave one blank row for visual separation]
- Maximum: =MAX(B7:B9)
- 75th Percentile: =QUARTILE(B7:B9,3)
- Median: =MEDIAN(B7:B9)
- 25th Percentile: =QUARTILE(B7:B9,1)
- Minimum: =MIN(B7:B9)
```

**統計が必要な列 (比較可能なメトリクス):**
- 収益成長率 %、売上総利益率 %、EBITDA 利益率 %、EPS
- EV/収益、EV/EBITDA、PER、配当利回り%、ベータ

**統計が必要ない列 (サイズ メトリック):**
- 売上高、EBITDA、純利益（絶対規模は企業規模により異なります）
- 時価総額、企業価値 (規模の異なる企業では比較できません)

**注意:** 視覚的に区別するために、会社データと統計の行の間に空白行を 1 行追加します。 「SECTOR STATISTICS」または「VALUATION STATISTICS」ヘッダー行を追加しないでください。

**四分位数が重要な理由:** 四分位数は、単なる平均ではなく分布を示します。 75 パーセンタイル倍数は、「プレミアム」企業の取引価格を示します。

<a id="section-3-valuation-multiples--investment-metrics"></a>
## セクション 3: 評価倍率と投資指標

<a id="core-valuation-columns-start-with-these"></a>
### コア評価列 (まずはこれらから始めてください)
1. **会社** - 業務セクションと同じ順序
2. **時価総額** - 現在の市場評価額
3. **企業価値** - 時価総額 ± 純負債/現金
4. **EV/収益** - 売上 1 ドルあたり市場が支払う金額
5. **EV/EBITDA** - 収益 1 ドルあたり市場が支払う金額
6. **PER** - 純利益に対する価格

<a id="optional-valuation-metrics-choose-based-on-context"></a>
### オプションの評価指標 (コンテキストに基づいて選択)
- **FCF 利回り** - FCF/時価総額 (現金重視の分析用)
- **PEG Ratio** - PER/成長率 (成長企業の場合)
- **株価純資産倍率（P/B）** - 市場価値と帳簿価額 (資産重視のビジネスの場合)
- **ROE/ROA** - 収益指標 (収益性の比較用)
- **収益/EBITDA CAGR** - 過去の成長率 (傾向分析用)
- **資産回転率** - 収益/資産 (業務効率化のため)
- **負債/資本** - レバレッジ (資本構造分析用)

**重要な原則:** 業界にとって重要なコアのマルチプルを 3 ～ 5 つ含めます。できるからといって、考えられるすべての指標を含めないでください。

<a id="formula-examples"></a>
### 計算式の例
```excel
// Core multiples - always include these
EV/Revenue: =[Enterprise Value]/[LTM Revenue]
EV/EBITDA: =[Enterprise Value]/[LTM EBITDA]
P/E Ratio: =[Market Cap]/[Net Income]

// Optional multiples - include if data available
FCF Yield: =[LTM FCF]/[Market Cap]
PEG Ratio: =[P/E]/[Growth Rate %]
```

<a id="cross-reference-rule"></a>
### 相互参照ルール
**重要:** 評価倍率は事業指標セクションを参照する必要があります。同じ生データを二度入力しないでください。収益が C7 にある場合、EV/収益の式は C7 を参照する必要があります。

<a id="statistics-block"></a>
### 統計ブロック
事業指標セクションと同じ構造: すべてのメトリックの最大、75パーセンタイル、中央値、25パーセンタイル、最小。企業データと統計を視覚的に分離するために、空白行を 1 行追加します。 「VALUATION STATISTICS」ヘッダー行を追加しないでください。

<a id="section-4-notes--methodology-documentation"></a>
## セクション 4: メモと方法論のドキュメント

<a id="required-components"></a>
### 必要なコンポーネント

**データソースと品質:**
- データはどこから来たのでしょうか? (S&P Kensho MCP、FactSet MCP、Daloopa MCP、ブルームバーグ、SEC 提出書類)
- どの期間が対象ですか? (2024 年第 4 四半期、監査済みの数値)
- どのように検証されましたか? (10-K/10-Q と照合済み)
- 注: 精度とトレーサビリティを向上させるために、利用可能な場合は MCP データ ソース (S&P Kensho、FactSet、Daloopa) を優先します。

**主要な定義:**
- EBITDA算出方法（売上総利益＋D&A、または営業利益＋D&A）
- フリーキャッシュフロー計算式（営業CF－設備投資）
- 特別なメトリクスの説明 (40 のルール、FCF転換率)
- 期間の定義 (LTM、CAGR 計算期間)

**評価方法:**
- 企業価値はどのように計算されましたか? (時価総額 + 純負債)
- どのような成長率が使用されましたか? (過去の CAGR、将来予測)
- 何か調整は行われましたか？ （一過性の項目を除外、利益率は正規化）

**分析フレームワーク:**
- 投資仮説とは何ですか？ (クラウド/SaaSの効率化)
- 最も重要な指標は何ですか? （キャッシュ創出、資本効率）
- 読者は統計をどのように解釈すべきでしょうか? (四分位数はコンテキストを提供します)

<a id="section-5-choosing-the-right-metrics-decision-framework"></a>
## セクション 5: 適切な指標の選択 (意思決定の枠組み)

<a id="start-with-what-question-am-i-answering"></a>
### 「何の質問に答えますか?」から始めましょう。

**「過小評価されているのはどの会社ですか?」**
→ 焦点: EV/収益、EV/EBITDA、PER、時価総額
→ スキップ: 運用の詳細、成長指標

**「どの会社が最も効率的ですか?」**
→ 注目: 売上総利益率、EBITDAマージン、FCF マージン、資産回転率
→スキップ: サイズ指標、絶対金額

**「最も早く成長している会社はどこですか?」**
→ 焦点: 収益成長率、EBITDA CAGR、ユーザー/顧客の成長
→ スキップ: マージン指標、レバレッジ比率

**「最も優れた現金生成手段はどれですか?」**
→ 焦点: FCF、FCF マージン、FCF転換率、設備投資の強度
→スキップ: EBITDA、PER

<a id="industry-specific-metric-selection"></a>
### 業界固有のメトリクスの選択

**ソフトウェア/SaaS:**
必須事項: 売上成長率、売上総利益率、40の法則
オプション: ARR、純ドル保持率、CAC ペイバック
スキップ: 資産回転率、在庫指標

**製造/産業:**
必須項目: EBITDAマージン、資産回転率、設備投資/収益
オプション: ROA、在庫回転数、バックログ
スキップ: 40 の法則、SaaS メトリクス

**金融サービス:**
必須: ROE、ROA、効率性比率、PER
オプション: 純金利マージン、貸倒引当金
スキップ：売上総利益率、EBITDA (銀行にとっては意味がありません)

**小売/電子商取引:**
必須事項: 売上成長率、売上総利益率、在庫回転率
オプション: 同一店舗売上高、顧客獲得コスト
スキップ: 重度の研究開発または設備投資の指標

<a id="the-5-10-rule"></a>
### 「5-10 ルール」

**5 つの事業指標** - 収益、成長、2 ～ 3 の利益率/効率の指標
**5 つの評価指標** - 時価総額、EV、3つの評価倍率
**= 合計 10 列** - ストーリーを伝えるのに十分ですが、スレッドが失われるほど多くはありません

15 を超えるメトリクスがある場合は、ノイズが含まれている可能性があります。容赦なく編集する。

<a id="section-6-best-practices--quality-checks"></a>
## セクション 6: ベストプラクティスと品質チェック

<a id="before-you-start"></a>
### 始める前に
1. **ピア グループを定義します** - 企業は真に比較可能である必要があります (ビジネス モデル、規模、地理が類似している)。
2. **適切な期間を選択してください** - LTM は季節性を平滑化します。四半期ごとにトレンドを示します
3. **事前に単位を標準化** - 数百万対数十億の決定はすべてに影響します
4. **データ ソースをマップする** - 各数値の出所を知る

<a id="as-you-build"></a>
### 構築するにつれて
1. **最初にすべての生データを入力してください** - 数式を記述する前に青色のテキストを完成させてください
2. **すべてのハードコーディングされた入力にセル コメントを追加します** - セルを右クリック → コメントの挿入 → 情報源または前提を記録

   **出典データの場合は、その出所を正確に引用してください:**
   - 例: 「ブルームバーグ ターミナル - MSFT 株式 DES、2024 年 10 月 2 日にアクセス」
   - 例: 「2024 年第 4 四半期 10-K 申告、42 ページ、明細項目「総収益」」
   - 例: 「2024 年 10 月 2 日時点のファクトセットのコンセンサス推定」
   - **可能な場合はハイパーリンクを含めます**: セルを右クリック → リンク → SEC ファイリング、データ ソース、またはレポートへの URL を貼り付けます

   **仮定について、その理由を説明してください:**
   - 例: 「同業他社の中央値に基づいて 15% の EBITDA マージンを想定、会社は開示していない」
   - 例: 「企業価値を時価総額＋純負債5,000万ドルとして推定 (第 3 四半期の貸借対照表から、第 4 四半期はまだ入手できません)」
   - 例: 「ストリートコンセンサス EPS 3.45 ドルに基づく将来の PER (12 人のアナリスト予想の平均)」

   **これが重要な理由**: 監査証跡、データ検証、仮定の透明性、将来の更新が可能になります。
3. **数式を行ごとに作成します** - 次に進む前に各計算をテストします
4. **ヘッダーには絶対参照を使用します** - $C$6 はヘッダー行をロックします
5. **一貫したフォーマット** - パーセンテージは小数点ではなくパーセンテージとして表示されます。
6. **条件付き書式を追加** - 外れ値を自動的に強調表示します

<a id="sanity-checks"></a>
### 健全性チェック
- **マージンテスト**: 売上総利益率 > EBITDA利益率 > 純利益率 (定義により常に真)
- **評価倍率の妥当性**: 
  - EV/収益: 通常 0.5 ～ 20 倍 (業界によって大きく異なります)
  - EV/EBITDA: 通常 8 ～ 25 倍 (業界全体でほぼ一定)
  - P/E: 通常 10 ～ 50 倍 (成長率によって異なります)
- **成長率と倍率の相関関係**: 通常、成長率が高いほど倍率も高くなります。
- **規模と効率のトレードオフ**: 多くの場合、大企業の方がマージンが優れています (規模の利点)

<a id="common-mistakes-to-avoid"></a>
### 避けるべきよくある間違い
❌ 時価総額と企業価値を計算式に混ぜる
❌ 分子と分母に異なる期間を使用する (LTM と四半期)
❌ セル参照の代わりに数式に数値をハードコーディングする
❌ **出典を引用するか、仮定を説明するセル コメントのないハードコーディングされた入力**
❌ SEC 提出書類またはデータソースが利用可能な場合、そこへのハイパーリンクが欠落している
❌ 明確な目的なしに多すぎるメトリクスを含める
❌ 比較対象外の会社（ビジネスモデルが異なる）を含む
❌ 古いデータを開示せずに使用する
❌ パーセンテージの平均値の計算が間違っている (中央値であるべき)

<a id="section-7-workflow--practical-tips"></a>
## セクション 7: ワークフローと実践的なヒント

<a id="step-by-step-process"></a>
### 段階的なプロセス
1. **構造のセットアップ** (30 分)
   - すべてのヘッダーを作成する
   - セルの書式設定 (入力の場合は青、数式の場合は黒)
   - 単位と日付参照をロックする

2. **データを収集** (60 ～ 90 分)
   - 一次情報源から取得（利用可能な場合は S&P Kensho MCP、FactSet MCP、Daloopa MCP、利用できない場合は Bloomberg、SEC）
   - すべての生の数値を青色で入力します
   - 注記のセクションに出典を記録する

3. **数式を作成する** (30 分)
   - 単純な比率（マージン）から始める
   - マルチプルへの進捗（EV/収益）
   - クロスチェックを追加します (利益率は妥当か？)

4. **統計の追加** (15 分)
   - すべての列の数式構造をコピーする
   - 範囲が正しいことを確認します (B7:B10 ではなく B7:B9)。
   - 四分位ロジックをチェックする

5. **品質管理** (30 分)
   - 健全性チェックを実行する
   - 数式参照を確認する
   - #DIV/0!または#REF!のエラーを確認する
   - 既知のベンチマークと比較する

6. **ドキュメント** (15 分)
   - メモセクションを完了する
   - データソースの追加
   - 方法論を定義する
   - 分析に日付スタンプを付ける

<a id="pro-tips"></a>
### プロのヒント
- **テンプレートの保存**: 一度作成すれば永久に再利用可能
- **外れ値のカラーコード**: 平均から2標準偏差を超えて離れた値の条件付き書式設定
- **ソース ファイルへのリンク**: ブルームバーグのスクリーンショットまたは SEC 提出書類へのハイパーリンク
- **バージョン管理**: 明確な日付を付けて「Comps_v1_2024-12-15」として保存します
- **共同レビュー**: 他の人に数式をチェックしてもらいます

<a id="section-10-red-flags--warning-signs"></a>
## セクション 10: 危険信号と警告標識

<a id="data-quality-issues"></a>
### データ品質の問題
🚩 期間が一貫していない (四半期と年次が混在)  
🚩 説明のないデータが欠落しています  
🚩 データソース間の大きな違い (10% を超える差異)

<a id="valuation-red-flags"></a>
### 評価に関する危険信号
🚩 EBITDA がマイナスの企業は EBITDA 倍率で評価されます (代わりに収益倍率を使用します)  
🚩 超成長ストーリーなしでPERが100倍を超える  
🚩 業界にとって意味のない利益率

<a id="comparability-issues"></a>
### 比較可能性の問題
🚩 会計年度末が異なる (タイミングの問題が発生する)  
🚩専業企業と複合企業の混在  
🚩 「コンプ」とラベル付けされた実質的に異なるビジネスモデル

**疑わしい場合は、その会社を除外してください。** 6 つの疑わしいコンプよりも、3 つの完璧なコンプを持っている方が良いです。

<a id="common-ratio-formulas"></a>
### 一般的な比率の公式
```excel
Gross Margin = Gross Profit / Revenue
EBITDA Margin = EBITDA / Revenue
FCF Margin = Free Cash Flow / Revenue
FCF Conversion = FCF / Operating Cash Flow
ROE = Net Income / Shareholders' Equity
ROA = Net Income / Total Assets
Asset Turnover = Revenue / Total Assets
Debt/Equity = Total Debt / Shareholders' Equity
```

<a id="key-principles-summary"></a>
## 主要原則の概要

1. **構造が洞察を促す** - 正しいヘッダーは正しい思考を促す
2. **少ないほど良い** - 重要な 5 ～ 10 の指標が重要でない 20 の指標を上回る
3. **質問の指標を選択してください** - 評価分析 ≠ 効率分析
4. **統計はパターンを示します** - 中央値/四分位値から平均以上のことが明らかになります
5. **透明性は複雑さに打ち勝つ** - 誰もが理解できるシンプルな公式
6. **比較可能性が重要です** - 悪い比較を強制するよりも除外する方が良いです
7. **選択を文書化します** - どの指標とその理由をメモセクションに説明します

## 継続的な改善

類似企業分析が完了したら、次のように尋ねます。
1. 統計から予期せぬ洞察が明らかになりましたか?
2. 分析を制限するようなデータのギャップはありましたか?
3. 利害関係者は、あなたが含めなかった指標を要求しましたか?
4. どれくらいの時間がかかりましたか? どれくらいの時間がかかるべきですか?
5. 次回これをさらに便利にするものは何でしょうか?

最良のコンプ分析は反復ごとに進化します。テンプレートを保存し、フィードバックから学び、意思決定者が実際に使用するものに基づいて構造を改良します。
