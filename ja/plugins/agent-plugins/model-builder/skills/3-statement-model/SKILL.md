<a id="3-statement-financial-model-template-completion"></a>
# 財務三表財務モデルのテンプレートの完成

損益計算書、貸借対照表、キャッシュ フロー計算書間の適切なリンクを備えた統合財務モデル テンプレートを完成および設定します。

<a id="-critical-principles--read-before-populating-any-template"></a>
## ⚠️重要な原則 — テンプレートへ入力する前にお読みください

**環境 — Office JS と Python:**
- **Excel 内で実行している場合 (Office アドイン / Office JS):** Office JS を直接使用します。 `range.formulas = [["=D14*(1+Assumptions!$B$5)"]]` を介して数式を記述します。派生セルには `range.values` を使用しないでください。個別の再計算はありません。 Excel はネイティブに計算します。タブを移動するには、`context.workbook.worksheets.getItem(...)` を使用します。
- **スタンドアロンの .xlsx ファイルを生成する場合:** Python/openpyxl を使用します。 `ws["D15"] = "=D14*(1+Assumptions!$B$5)"` と書き込み、配信前に `recalc.py` を実行します。
- **Office JS マージ セルの落とし穴:** `.merge()` を呼び出してから、マージされた範囲に `.values` を設定しないでください。範囲はまだマージ前のサイズを報告するため、`InvalidArgument` がスローされます。代わりに、左上のセルのみに値を書き込み、全範囲を結合してフォーマットします: `ws.getRange("A1").values = [["INCOME STATEMENT"]]; const h = ws.getRange("A1:G1"); h.merge(); h.format.fill.color = "#1F4E79";`
- 以下のすべての原則は、どちらの環境でも同様に適用されます。

**数値の固定入力より数式を優先（必須）:**
- すべての予測セル、ロールフォワード、リンケージ、および小計は Excel の数式である必要があります。事前に計算された値ではありません。
- Python/openpyxl を使用する場合: 計算結果 (`ws["D15"] = 12500`) ではなく、数式文字列 (`ws["D15"] = "=D14*(1+Assumptions!$B$5)"`) を書き込みます。
- ハードコードされた数値を含める必要がある唯一のセルは次のとおりです: (1) 過去の実績値、(2) [仮定] タブの仮定要因
- Python で値を計算し、その結果をセルに書き込んでいる場合は、やめてください。代わりに式を書きます。
- 理由: シナリオが切り替わったり、前提が変化したりした場合には、モデルを柔軟にする必要があります。ハードコードは、すべてのダウンストリーム整合性チェックをサイレントに破ります。

**ユーザーと一緒に段階的に確認します:**
1. **テンプレートのマッピング後** → 特定したタブ/セクションをユーザーに表示し、セルに触れる前に確認してください。
2. **履歴を入力した後** → ユーザーに履歴ブロックを表示し、値/期間がソース データと一致することを確認します。
3. **IS 予測を構築した後** → 小計チェックを実行し、予測された IS をユーザーに表示し、BS に移動する前に確認します。
4. **BS構築後** → 期間ごとの残高確認（資産=L+E）をユーザーに表示し、CFに移行する前に確認
5. **CF 構築後** → 現金残高の照合 (CF 終了キャッシュ = BS キャッシュ) をユーザーに表示し、確定する前に確認します。
6. **モデル全体をエンドツーエンドで入力して完成したものとして提示しないでください** — 各財務諸表で中断し、作業を示し、エラーを早期にキャッチします

<a id="formatting--professional-bluegrey-palette-default-unless-templateuser-specifies-otherwise"></a>
## 書式設定 — プロフェッショナル ブルー/グレー パレット (テンプレート/ユーザーが別途指定しない限りデフォルト)

**色は最小限に抑えてください。** セルの塗りつぶしには青とグレーのみを使用してください。緑、黄色、オレンジ、または複数のアクセントカラーを導入しないでください。クリーンなモデルは抑制を使用します。

| 要素 | 埋める | フォント |
|---|---|---|
| セクションヘッダー（IS/BS/CFタイトル） | ダークブルー `#1F4E79` | 白太字 |
| 列ヘッダー (FY2024A、FY2025E など) | ライトブルー `#D9E1F2` | 黒太字 |
| 入力セル (履歴、仮定要因) | ライトグレー `#F2F2F2` または白 | ブルー `#0000FF` |
| 数式セル | ホワイト | ブラック |
| タブ間リンク | ホワイト | グリーン `#008000` |
| チェック行／主要合計 | ミディアムブルー `#BDD7EE` | 黒太字 |

**これは、青 3 色 + グレー 1 つ + 白です。** テンプレートに独自の配色がある場合は、代わりにテンプレートに従います。

フォント色はセルが*何か*（入力／数式／リンク）を示します。塗りつぶし色は*どこか*（見出し／データ／チェック）を示します。

<a id="model-structure"></a>
## モデルの構造

<a id="identifying-template-tab-organization"></a>
### 「テンプレート」タブの構成の識別

テンプレートによって、タブの命名規則と構成が異なります。入力する前に、すべてのタブを確認してテンプレートの構造を理解してください。以下は一般的なタブ名とその一般的な内容です。

| 一般的なタブ名 | 探すべきコンテンツ |
|------------------|----------------------|
| IS、P&L、Income Statement | 損益計算書 |
| BS、貸借対照表 | 貸借対照表 |
| CF、CFS、キャッシュフロー | キャッシュフロー計算書 |
| WC、Working Capital | 運転資金スケジュール |
| DA、D&A、減価償却費、PP&E | 減価償却費と償却スケジュール |
| 借金、借金スケジュール | 借金スケジュール |
| NOL、税金、DTA | 純営業損失スケジュール |
| 仮定、入力、要因 | ドライバーの仮定と入力 |
| チェック、監査、検証 | エラーチェックダッシュボード |

**テンプレートレビューチェックリスト**
- テンプレートにどのタブが存在するかを特定します (すべてのテンプレートにすべてのスケジュールが含まれているわけではありません)
- 上記にリストされていないテンプレート固有のタブに注意してください
- タブの依存関係を理解する (例: どのスケジュールが主要財務諸表にフィードされるか)
- 各タブで入力セルと数式セルを特定する

<a id="understanding-template-structure"></a>
### テンプレートの構造を理解する

テンプレートにデータを入力する前に、既存のレイアウトをよく理解し、データが正しい場所に入力され、数式がそのまま残っていることを確認してください。

**行構造の識別**
- 各タブの上部にあるモデルのタイトルを見つけます。
- セクションヘッダーとその視覚的な分離を特定する
- $ millions、%、x などを示す単位の行を見つけます。
- 実績期間と推定期間を区別する列ヘッダーに注意してください
- 期間ラベルを確認します（例：FY2024A、FY2025E）
- 入力セルと数式セルを識別します (通常はフォントの色で区別されます)

**カラム構造の特定**
- 左端の列の品目ラベルを確認します
- 過去の年が予測年よりも前であることを確認する
- 過去の期間と予測された期間を区切る視覚的な境界線に注目してください
- すべてのタブにわたって列の順序が一貫していることを確認する

**名前付き範囲の操作**
テンプレートでは、キーの入力と出力に名前付き範囲を使用することがよくあります。データを入力する前に:
- テンプレート内の既存の名前付き範囲を確認します (Excel の数式 → 名前マネージャー)
- 一般的な名前付き範囲には、収益成長率、コストの割合、主要な出力値 (純利益、EBITDA、負債総額、現金)、シナリオ セレクター セルが含まれます。
- これらの名前付き範囲に入力されるセルに入力されていることを確認してください。

<a id="projection-period"></a>
### 予測期間
- テンプレートは通常、直近の実績年から 5 年先を予測します。
- 過去の列 (A) と予測された列 (E) が明確に分離されていることを確認します。
- 列に会計年度表記が使用されていることを確認します（例：FY2024A、FY2025E）

<a id="margin-analysis"></a>
## 利益率分析

**注: 次の利益率分析は、ユーザーから指示された場合、またはテンプレートで明示的に要求されている場合にのみ実行してください。プロンプトが表示されない場合は、このセクションをスキップしてください。**

[損益計算書 (IS)] タブで利益率を計算して表示し、業務効率を追跡し、競合他社との比較を可能にします。

<a id="core-margins-to-include"></a>
### 含める基本利益率

| 利益率 | 計算式 | 測定内容 |
|--------|---------|------------------|
| 売上総利益率 | 売上総利益 / 売上高 | 価格決定力、生産効率 |
| EBITDAマージン | EBITDA / 収益 | コア営業利益率 |
| EBITマージン | EBIT / 収益 | D&A後の営業利益率 |
| 当期純利益率 | 当期純利益 / 売上高 | 最終的な収益性 |

<a id="income-statement-layout-with-margins"></a>
### 利益率を併記した損益計算書のレイアウト

各利益項目のすぐ下に利益率を表示します。
- 売上総利益の直下に売上総利益率（%）
- EBITの直下にEBIT利益率（%）
- EBITDAの直下にEBITDA利益率（%）
- 純利益の直下に純利益率（%）

<a id="credit-metrics"></a>
## 信用指標

**注: 次の信用分析は、ユーザーによって要求された場合、またはテンプレートで明示的に要求されている場合にのみ実行してください。プロンプトが表示されない場合は、このセクションをスキップしてください。**

[貸借対照表 (BS)] タブで信用/レバレッジの指標を計算して表示し、財務の健全性、債務能力、および契約の遵守状況を評価します。

<a id="core-credit-metrics-to-include"></a>
### 含めるべきコア信用指標

| メトリック | 計算式 | 測定内容 |
|--------|---------|------------------|
| 負債総額 / EBITDA | 負債総額 / LTM EBITDA | レバレッジ倍率 |
| 純負債/EBITDA | (負債合計 - 現金) / LTM EBITDA | 現金を差し引いたレバレッジ |
| インタレスト・カバレッジ | EBITDA / 支払利息 | 債務返済能力 |
| 負債／総資本 | 負債合計 / (負債合計 + 資本) | 資本構成 |
| 負債/資本 | 負債合計 / 資本合計 | 財務レバレッジ |
| 流動比率 | 流動資産 / 流動負債 | 短期流動性 |
| 当座比率 | (流動資産 - 棚卸資産) / 流動負債 | 即時流動性 |

<a id="credit-metric-hierarchy-checks"></a>
### 信用指標階層チェック

Upside が最も強い信用プロファイルを示していることを検証します。
- レバレッジ: アップサイド < ベース < ダウンサイド (低いほど良い)
- カバレッジ: アップサイド > ベース > ダウンサイド (高いほど良い)
- 流動性: アップサイド > ベース > ダウンサイド (高いほど良い)

<a id="covenant-compliance-tracking"></a>
### 規約遵守状況の追跡

債務規約がわかっている場合は、実際の指標と規約のしきい値を比較する明示的なコンプライアンス チェックを追加します。

<a id="scenario-analysis-base--upside--downside"></a>
## シナリオ分析（ベース/アップサイド/ダウンサイド）

CHOOSE または INDEX/MATCH 式を使用して、[Assumptions] タブのシナリオ切り替え (ドロップダウン) を使用します。

| シナリオ | 説明 |
|----------|-------------|
| 基本ケース | 経営陣のガイダンスまたはコンセンサス推定 |
| アップサイドケース | 指針を上回る成長、利益率の拡大 |
| ダウンサイドケース | トレンドを下回る成長、利益率の圧縮 |

**感度分析する主要因**：売上成長率、売上総利益率、SG&A %、DSO/DIO/DPO、CapEx %、金利、税率。

**シナリオ監査チェック**: トグルスイッチは、すべてのステートメント、すべてのシナリオでBSの貸借が一致すること、現金残高の照合、階層保持 (NI、EBITDA、FCF、利益率のアップサイド > ベース > ダウンサイド) を切り替えます。

## SEC提出書類データの抽出

<a id="completing-model-templates"></a>
## モデルテンプレートの完成

このセクションでは、既存の数式を維持し、データの整合性を確保しながら、財務三表の財務モデル テンプレートを完成させるための一般的なガイダンスを提供します。

<a id="step-1-analyze-the-template-structure"></a>
### ステップ 1: テンプレート構造を分析する

データを入力する前に、テンプレートを徹底的に確認して、そのアーキテクチャを理解してください。

**入力と数式セルの識別**
- 入力セルと数式セルを区別する視覚的な手がかり (フォントの色、セルの陰影) を探します。
- 一般的な規則: 青色のフォント = 入力、黒色のフォント = 数式、緑色のフォント = 他のシートへのリンク
- Excel の参照元／参照先のトレース（数式 → 参照元のトレース） を使用してセルの関係を理解する
- キー入力を制御する可能性のある名前付き範囲を確認します (数式 → 名前マネージャー)

**テンプレートのフローをマップする**
- どのタブが他のタブにフィードしているかを特定します (例: Assumptions → IS → BS → CF)
- サポートするスケジュールと、主要財務諸表との関連に注意してください。
- 入力する前に、テンプレートの特定の項目と構造を文書化します。

<a id="step-2-filling-in-data-without-breaking-formulas"></a>
### ステップ 2: 数式を壊さずにデータを入力する

**データ入力の黄金律**

| ルール | 説明 |
|------|-------------|
| 入力セルのみを編集する | 数式を意図的に置き換えない限り、数式を含むセルを上書きしないでください。 |
| セル参照を保持する | データをコピーするときは、値の貼り付け (Ctrl+Shift+V) を使用して、ソースの書式設定で数式が上書きされないようにします。 |
| テンプレートの単位を一致させる | データを入力する前に、テンプレートで数千、数百万、または実際の値が使用されているかどうかを確認してください |
| 符号規則を尊重する | テンプレートの既存の符号規則に従います (例: 経費をプラスまたはマイナスとして表示) |
| 循環参照をチェックする | テンプレートで反復計算を使用する場合は、[反復計算を有効にする] がオンになっていることを確認してください。 |

**安全なデータ入力プロセス**
1. 入力用に指定された正確なセルを特定します (通常は強調表示されるかラベルが付けられます)。
2. 最初に履歴データを入力し、式がそれらの期間に対して正しく計算されていることを確認します。
3. 予測計算にフィードを与える仮定要因を入力します
4. 計算された出力をレビューして、数式が意図したとおりに機能していることを確認します
5. 数式セルを変更する必要がある場合は、変更を加える前に元の数式を文書化してください。

**事前に構築された数式の処理**
- 数式がまだ入力していないセルを参照している場合は、すべての入力が完了するまで一時的なエラー (#REF!、#DIV/0!) が発生することが予想されます。
- 数式が予期しない結果を生成した場合、参照元を追跡して入力の欠落または不正確を特定します
- すべてのタブにわたる数式の依存関係を確認せずに行/列を削除しないでください。

<a id="step-3-validating-formulas"></a>
### ステップ 3: 式の検証

**式の整合性チェック**

テンプレートの出力に依存する前に、数式が正しく機能していることを検証してください。

| チェックタイプ | 方法 |
|------------|--------|
| 参照元をたどる | 数式セルを選択→「数式」→「参照元のトレース」を選択して、正しい入力を参照していることを確認します。 |
| トレース依存関係 | キー入力が予想される出力セルに流れることを確認する |
| 式を評価する | [数式] → [数式の評価] を使用して、複雑な計算を段階的に実行します。 |
| ハードコードをチェックする | 予測式は仮定を参照する必要があり、ハードコードされた値を含めるべきではありません |
| 既知の値でテストする | 簡単なテスト値を入力して、数式が期待どおりの結果を生成することを確認します。 |
| タブ間の一貫性 | すべての予測期間にわたって同じ数式ロジックが適用されるようにする |

**注意すべき一般的な数式の問題**
- 絶対参照と相対参照が混在しているため、期間をまたいでコピーすると不正確な結果が発生する
- 外部ファイルへのリンクの破損または範囲の削除 (#REF! エラー)
- 収益が増加する前の初期の期間におけるゼロによる除算 (#DIV/0! エラー)
- 循環参照警告 (利息計算のために意図的に行われている可能性があります)
- 予測列間で数式が一貫していない (差異を見つけるには Ctrl+\ を使用します)

**クロスタブ連携の検証**
- 複数のタブに表示される値がリンクされていること (重複していないこと) を確認します。
- スケジュール合計が主な明細書の対応する明細項目に関連付けられていることを確認します。
- 期間ラベルがすべてのタブで揃っていることを確認します

<a id="step-4-quality-checks-by-sheet"></a>
### ステップ 4: シートごとの品質チェック

テンプレートを入力した後、各シートで次の検証チェックを実行します。

**損益計算書 (IS) の品質チェック**
- 収益数値は過去の期間のソース データと一致します
- すべての経費項目の合計が報告された合計となります
- 小計 (総利益、EBIT、EBT、純利益) が正しく計算される
- 税計算ロジックが適切である（損失を正しく処理する）
- 予測ドライバー参照仮定タブ (ハードコードなし)
- 前期比の変化は方向性として合理的である

**貸借対照表 (BS) の品質チェック**
- 各期の資産 = 負債 + 資本 (一次チェック)
- 現金残高はキャッシュフロー計算書の最終現金と一致します
- 運転資本勘定はサポートスケジュールに関連付けられています（該当する場合）
- 利益剰余金は正しくロールフォワードされます: 以前の RE + 純利益 - 配当 +/- 調整 = 終了 RE
- 債務残高は債務スケジュールに関連付けられます (該当する場合)
- すべての貸借対照表項目には適切な符号が付いています (資産はプラス、ほとんどの負債はプラス)

**キャッシュ フロー計算書 (CF) の品質チェック**
- CFOトップの純利益は損益計算書の純利益と一致
- 非現金アドバック (D&A、SBC など) はソーススケジュール/ステートメントに関連付けられます。
- 運転資本の変化には正しい符号があります (資産の増加 = 現金の使用 = マイナス)
- 設備投資は PP&E スケジュールまたは固定資産のロールフォワードに関連付けられます
- 財務活動は BS の負債および資本勘定の変更に関係します
- 期末現金は貸借対照表の現金と一致します
- 期首現金は前期末現金と等しい

**スケジュール品質チェックのサポート**
- 期首残高は前期期末残高と等しい
- ロールフォワード ロジックが完了しました (開始 + 追加 - 控除 = 終了)
- スケジュール合計は主な明細行項目に関連付けられます
- 計算で使用される仮定が一致する [仮定] タブ

<a id="step-5-cross-statement-integrity-checks"></a>
### ステップ 5: 財務諸表間の整合性チェック

個々のシートを検証した後、財務三表が適切に統合されていることを確認します。

| チェックする | 計算式 | 期待される結果 |
|-------|---------|-----------------|
| 貸借対照表のバランス | 資産 - 負債 - 資本 | = 0 |
| 現金残高の照合 | CF期末キャッシュ - BSキャッシュ | = 0 |
| 純利益リンク | IS 当期純利益 - CF 開始純利益 | = 0 |
| 利益剰余金 | 以前の RE + NI - 配当 - BS 終了 RE | = 0 (必要に応じて SBC/その他の項目を調整します) |

<a id="step-6-final-review"></a>
### ステップ 6: 最終レビュー

モデルが完成したと考える前に、次のことを行ってください。
- すべてのシナリオ (該当する場合) を切り替えて、それぞれのケースでチェックに合格することを確認します。
- #REF!、#DIV/0!、#VALUE!、#NAME? の全エラーを確認し、解消または文書化します
- すべての入力セルが入力されていることを確認します (プレースホルダー値を検索します)。
- すべてのタブで単位が一貫していることを確認する
- 追加の変更を加える前に、クリーンなバージョンを保存してください

## モデルの検証と監査

このセクションでは、完成したテンプレートのすべての検証チェックと監査手順を統合します。

<a id="core-linkages-must-always-hold"></a>
### コアリンケージ (常に保持する必要があります)

すべての式の詳細については、[references/formulas.md](../../../../vertical-plugins/financial-analysis/skills/3-statement-model/references/formulas.md) を参照してください。

| チェックする | 計算式 | 期待される結果 |
|-------|---------|-----------------|
| 貸借対照表のバランス | 資産 - 負債 - 資本 | = 0 |
| 現金残高の照合 | CF期末キャッシュ - BSキャッシュ | = 0 |
| 毎月の現金と年間の現金 | 期末現金 (月次) - 期末現金 (年次) | = 0 |
| 純利益リンク | IS 当期純利益 - CF 開始純利益 | = 0 |

| エクイティファイナンス | Δ普通株式/APIC (BS) - 株式発行 (CFF) | = 0 |
| 0年目の自己資本 | 調達した出資金（0年目） - 開始時の自己資本 (1 年目) | = 0 |

<a id="circular-reference-handling"></a>
### 循環参照の処理

支払利息は循環性を生み出します: 利息 → 純利益 → 現金 → 負債残高 → 利息

Excel で反復計算を有効にするには、[ファイル] → [オプション] → [数式] → [反復計算を有効にする] を選択します。最大反復を 100 に、最大変化を 0.001 に設定します。 [前提条件] タブにサーキット ブレーカーの切り替えを追加します。

<a id="check-categories"></a>
### カテゴリを確認する

**セクション 1: 通貨の一貫性**
- 前提条件で特定および文書化された通貨
- すべてのタブで一貫した通貨記号とスケールが使用されます
- 単位行がモデル通貨と一致する

**セクション 2: 貸借対照表の健全性**
- 資産＝負債＋資本（各期）
- 計算式: 資産 - 負債 - 資本 (must = 0)

**セクション 3: キャッシュ フローの完全性**
- BS との現金連動 (CF 期末キャッシュ = BS キャッシュ)
- 月次キャッシュと年次キャッシュ: 期末キャッシュ (月次) = 期末キャッシュ (年次)
- NIはISと一致します (CF 純利益 = IS 純利益)
- D&A はスケジュールと連動
- SBCはISと結びついている
- ΔAR、Δ在庫、ΔAP はWC（運転資本）のスケジュールと連動
- 設備投資は DA スケジュールと連動する

**セクション 4: 利益剰余金**
- RE ロールフォワード チェック: 以前の RE + NI + SBC - 配当 = 終了 RE
- デバッグ用にコンポーネントの内訳を表示する

**セクション 5: 運転資本**
- AR、棚卸資産、AP と BS の連携
- DSO、DIO、DPO の妥当性チェック (正常範囲外の場合にフラグを立てる)

**セクション 6: 債務スケジュール**
- BS に関連する負債総額（流動部分＋長期負債）
- 利息計算はISと連動

**セクション 6b: 株式による資金調達**
- BS普通株式/APIC増額に伴う株式発行収入
- 資本による現金の増加 = 資本勘定の増加 (バランスが必要)
- 株式調達額の照合: Δ普通株式/APIC (BS) = 株式発行 (CFF) (必須 = 0)
- 0年目の自己資本照合: 調達した出資金（0年目） = 開始時の自己資本 (1 年目)

**セクション 6c: NOL スケジュール**
- 開始 NOL (1 年目 / 設立) = 0 (新しいビジネスは NOL ゼロから始まります)
- NOLはEBT < 0の場合にのみ増加します（NOLを生成するには損失を実現する必要があります）
- DTA は BS に関連付けられます (NOL スケジュール DTA = BS 繰延税金資産)
- NOL使用額 ≤ EBTの80% (2017年より後の連邦制限)
- NOL残高はマイナスではない（利用可能な以上は利用できない）
- NOLはEBT < 0の場合にのみ生成されます
- 課税所得 ≤ 0 の場合、税金費用 = 0

**セクション 7: シナリオの階層**
- 絶対指標: アップサイド > ベース > ダウンサイド (NI、EBITDA、FCF)
- 利益率: アップサイド > ベース > ダウンサイド (GM%、EBITDA%、NI%)
- 信用指標: レバレッジのアップサイド < ベース < ダウンサイド (反転)

**セクション 8: フォーミュラの完全性**
- COGS、S&M、G&A、R&D、SBC は収益の % によって決まります (ハードコードなし)
- 予測年全体にわたって一貫した計算式
- #REF!、#DIV/0!、#VALUE! のエラーがないことを確認します

**セクション 9: 信用指標のしきい値**
- コベナントのしきい値に基づいてメトリクスに緑/黄/赤のフラグを付ける
- 危険信号の概要

<a id="master-check-formula"></a>
### マスターチェックフォーミュラ

すべてのセクションのステータスを 1 つのマスター チェックに集約します。
- 全セクション合格の場合→「✓ ALL CHECKS PASS」
- いずれかのセクションが失敗した場合 → 「✗ エラーが検出されました - 以下を確認してください」

<a id="quick-debug-workflow"></a>
### クイック デバッグ ワークフロー

マスターステータスにエラーが表示される場合:
1. スクロールして赤く強調表示されたセクションを見つけます
2. どのチェック カテゴリに失敗があるかを特定する
3. ソースタブに移動して調査します
4. 根本的な問題を修正する
5. [チェック] タブに戻って解決策を確認します
