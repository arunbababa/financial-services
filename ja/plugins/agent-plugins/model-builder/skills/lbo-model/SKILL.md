<a id="template-requirement"></a>
## テンプレートの要件

**このスキルは LBO モデルのテンプレートを使用します。最初に必ず添付されたテンプレート ファイルを確認してください。**

LBO モデルを開始する前に:
1. **テンプレート ファイルが添付/提供されている場合**: そのテンプレートの構造を正確に使用します。それをコピーし、ユーザーのデータを入力します。
2. **テンプレートが添付されていない場合**: ユーザーに尋ねます: *「使用したい特定の LBO テンプレートはありますか? ない場合は、資金調達・使途表、運用モデル、債務スケジュール、投資リターン分析を含む標準テンプレートを使用できます。」*
3. **標準テンプレートを使用する場合**: 出発点として `examples/LBO_Model.xlsx` をコピーし、ユーザーの仮定を入力します。

**重要**: `LBO_Model.xlsx` のようなファイルが添付されている場合は、それをテンプレートとして使用する必要があります。最初から構築しないでください。テンプレートが複雑に見えたり、必要以上の機能が含まれている場合でも、テンプレートをコピーしてユーザーの要件に合わせて調整してください。テンプレートが提供されている場合は、決して「最初から構築する」ことを決めないでください。

<a id="critical-instructions-for-claude---read-first"></a>
## クロードへの重要な指示 - 最初にお読みください

<a id="environment-office-js-vs-python"></a>
### 環境: Office JS と Python

**Excel 内で実行している場合 (Office アドイン / Office JS 環境):**
- Office JS (`Excel.run(async (context) => {...})`) を直接使用します。Python/openpyxl は使用しないでください。
- `range.formulas = [["=B5*B6"]]` 経由で数式を記述する — Office JS 数式はライブ ワークブックでネイティブに再計算されます
- ハードコードよりも式を優先するという同じルールが適用されます。計算すべきものには `range.formulas` を設定し、決して `range.values` を設定しないでください。
- 青/黒/紫/緑の規則には、`range.format.font.color` / `range.format.fill.color` を使用します。
- 別の再計算ステップは必要ありません - Excel がネイティブに計算を処理します
- **マージされたセルの落とし穴:** `.merge()` を呼び出してから、マージされた範囲に `.values` を設定しないでください (`InvalidArgument` がスローされます。範囲は依然として元のディメンションを報告します)。代わりに、左上のセルのみに値を書き込み (`ws.getRange("A7").values = [["SOURCES & USES"]]`)、全範囲をマージしてフォーマットします (`ws.getRange("A7:F7").merge(); ws.getRange("A7:F7").format.fill.color = "#1F4E79";`)。

**スタンドアロンの .xlsx ファイルを生成する場合 (ライブ Excel セッションがない場合):**
- 以下で説明するように Python/openpyxl を使用します。
- 数式文字列 (`ws["D20"] = "=B5*B6"`) を書き込み、配信前に `recalc.py` を実行します。

このスキルの残りの部分は openpyxl の例を使用して書かれていますが、同じ原則が Office JS にも適用され、API 呼び出しを変換するだけです。

<a id="core-principles"></a>
### 基本原則
* **すべての計算は Excel の数式である必要があります** - Python で値を計算し、結果をセルにハードコードしないでください。 openpyxl を使用する場合は、`cell.value = 1250` (計算結果) ではなく、`cell.value = "=B5*B6"` (式文字列) を記述します。モデルは動的であり、入力が変更されると更新される必要があります。
* **テンプレート構造を使用する** - `examples/LBO_Model.xlsx` の構成またはユーザーが提供したテンプレートに従います。独自のレイアウトを考え出さないでください。
* **適切なセル参照を使用する** - すべての数式は適切なセルを参照する必要があります。他のセルから取得されるはずの数値を入力しないでください。
* **符号規則の一貫性を維持する** - テンプレートで使用されている符号規則に従います (アウトフローにネガティブを使用するものもあれば、ポジティブを使用するものもあります)。全体を通して一貫性を保ってください。
* **セクションごとに作業し、各ステップでユーザーに確認してください** - 1 つのセクションを完全に完了し、何が構築されたかをユーザーに示し、セクションの検証チェックを実行して、次のセクションに進む前に確認を得ます。モデル全体をエンドツーエンドで構築してから提示しないでください。後のセクションは前のセクションに依存しているため、リターンがすでに構築された後に資金調達・使途で間違いを見つけると、あらゆる場所でやり直しが必要になります。

<a id="formula-color-conventions"></a>
### 数式の文字色の規則
* **青 (0000FF)**: ハードコードされた入力 - 他のセルを参照しない入力された数値
* **黒 (000000)**: 計算を含む数式 - 演算子または関数を使用した任意の数式 (`=B4*B5`、`=SUM()`、`=-MAX(0,B4)`)
* **紫 (800080)**: **同じタブ**のセルへのリンク - 計算なしの直接参照 (`=B9`、`=B45`)
* **緑 (008000)**: **別のタブ**のセルへのリンク - クロスシート参照 (`=Assumptions!B5`、`='Operating Model'!C10`)

<a id="fill-color-palette--professional-blues--greys-default-unless-usertemplate-specifies-otherwise"></a>
### 塗りつぶしカラー パレット — プロフェッショナル ブルー & グレー (ユーザー/テンプレートが別途指定しない限りデフォルト)
* **最小限に抑えてください** — セルの塗りつぶしには青とグレーのみを使用します。緑、黄色、赤、または複数のアクセントを導入しないでください。プロの LBO モデルは色使いを抑えます。
* **デフォルトの塗りつぶしパレット:**
  * **セクション ヘッダー** (資金調達・使途表、オペレーティング モデルなど): 濃い青の `#1F4E79`、白の太字
  * **列ヘッダー** (1 年目、2 年目など): 水色の `#D9E1F2`、黒の太字
  * **入力セル**: ライトグレー `#F2F2F2` (または白) — 青い *フォント* がシグナルであり、塗りつぶしが二次的です
  * **数式/計算セル**: 白、塗りつぶしなし
  * **主要な出力** (IRR、MOIC、出口資本): 中青色の `#BDD7EE`、黒の太字
* **これがパレット全体です。** ブルー 3 色 + グレー 1 色 + ホワイト。テンプレートで独自の色が使用されている場合は、代わりにテンプレートに従います。
* 注: 上記の青/黒/紫/緑の **フォント** の色は、入力、式、リンクを区別するためのものです。これらは、ここでは **fill** パレットとは別のものであり、両方とも連携して機能します。

<a id="number-formatting-standards"></a>
### 数値の書式設定の標準
* **通貨**: テンプレートに応じて `$#,##0;($#,##0);"-"` または `$#,##0.0`
* **パーセンテージ**: `0.0%` (小数点 1 桁)
* **倍数**: `0.0"x"` (小数点以下 1 桁)
* **MOIC/詳細な比率**: `0.00"x"` (精度のため小数点以下 2 桁)
* **すべての数値セル**: 右揃え

<a id="template-analysis-phase---do-this-first"></a>
## テンプレート分析フェーズ - 最初にこれを実行します

数式を入力する前に、テンプレートを徹底的に調べてください。

1. **構造をマップする** - 各セクションがどこに存在し、それらが相互にどのように関係しているかを特定します。どのセクションが他のセクションに影響を与えるかに注意してください。

2. **タイムラインを理解する** - どの列がどの期間を表しているか? 「クロージング」または「プロフォーマ」列はありますか?予測期間はどこから始まりますか?

3. **入力セルと数式セルを識別する** - テンプレートでは多くの場合、色分け、境界線、または陰影を使用して、入力と数式が必要なセルを示します。これらの慣例を尊重してください。

4. **既存のラベルを注意深くお読みください** - 行ラベルは、どのような計算が予想されるかを正確に示します。思い込みではなく、テンプレートが何を要求しているのかを読んでください。

5. **既存の数式を確認してください** - 一部のテンプレートは部分的に入力されています。特に指示がない限り、正しく動いている数式を上書きしないでください。

6. **テンプレート固有の規則に注意してください** - 符号規則、小計の構造、セクションの編成方法、コンポーネントごとに個別のタブがあるかどうかなど。

## 数式の入力 - 一般的なアプローチ

数式が必要なセルごとに、次の階層に従います。

<a id="step-1-check-the-template"></a>
### ステップ 1: テンプレートを確認する
* セルにはすでに数式が含まれていますか? 「はい」の場合は、それが正しいことを確認して次に進みます。
* 予想される計算を示すコメントやメモはありますか?
* 行/列のラベルによって計算が明確になりますか?

<a id="step-3-apply-standard-practice"></a>
### ステップ 3: 標準プラクティスを適用する
* テンプレートもユーザーも指定しない場合は、標準の LBO モデリング規則を使用します。
* 自分が立てた仮定をすべて文書化する
* 本当に不明な場合は、ユーザーに尋ねてください

<a id="common-problem-areas"></a>
## 一般的な問題領域

次の計算パターンは、LBO モデル全体で問題を引き起こすことがよくあります。次のような場合には特に注意してください。

<a id="balancing-sections"></a>
### バランシングセクション
* 2 つのセクションが等しくなければならない場合 (例: 資金調達額 = 資金使途額)、通常、1 つの項目が「プラグ」 (差額調整値) になります。
* どのアイテムがプラグであるかを特定し、差として計算します

<a id="tax-calculations"></a>
### 税金の計算
* 税金の計算式では、関連する所得明細と税率のみを参照する必要があります。
* 無関係なセクション (債務スケジュールなど) を参照しないでください。
* 損失が節税効果となるのか、それとも単純に無視されるのかを検討する

<a id="interest-and-circular-references"></a>
### 利息と循環参照
* 利息の計算がキャッシュ フローの影響を受ける残高を参照する場合、循環性が生じる可能性があります。
* 循環参照を解除するには、**期首残高** (平均または終了値ではない) を使用します。
* パターン: 利息 → キャッシュ フロー → 支払 → 期末残高 (利息が期末残高を使用する場合、これは循環します)

<a id="debt-paydown--cash-sweeps"></a>
### 債務返済／キャッシュスイープ
* 複数の債務トランシェが存在する場合、通常は優先順位があります
* キャッシュスイープでは優先順位のウォーターフォールを尊重する必要があります
* 残高はマイナスにはなりません - MAX 関数または MIN 関数を適切に使用してください

<a id="returns-calculations-irrmoic"></a>
### 投資リターン計算 (IRR/MOIC)
* キャッシュ フローには正しい符号が必要です: 投資 = マイナス、回収額 = プラス
* XIRRを使用する場合は、対応する日付が必要です
* IRR を使用する場合、キャッシュ フローは連続した期間である必要があります
* MOIC = 総回収額 / 総投資額

<a id="sensitivity-tables"></a>
### 感度テーブル
* **奇数寸法を使用してください** (5×5 または 7×7) — 4×4 や 6×6 は決して使用しないでください。奇数の寸法では真の中央セルが保証されます。
* **中央のセル = 基本ケース。** モデルの実際の仮定を中心に対称的に行軸と列軸の値を構築します (たとえば、基本エントリの倍数 = 10.0x、軸 = `[8.0x, 9.0x, 10.0x, 11.0x, 12.0x]` の場合)。中央セルの IRR/MOIC は、モデルの実際の IRR/MOIC 出力と等しくなければなりません。これは、テーブルが正しく配線されている証拠です。
* **中央のセルを強調表示します** - 中程度の青色の塗りつぶし (`#BDD7EE`) + 太字フォントで、基本ケースが視覚的に固定されるようにします。
* Excel の DATA TABLE 関数は openpyxl では機能しない可能性があります。代わりに、行/列ヘッダーを参照する明示的な数式を記述してください。
* 各セルには異なる値が表示されるはずです。すべて同じであれば、数式は正しく変化していません。
* 混合参照を使用します (例: 行入力の場合は `$A5`、列入力の場合は `B$4`)

<a id="verification-checklist---run-after-completion"></a>
## 検証チェックリスト - 完了後に実行

<a id="run-formula-validation"></a>
### 数式検証の実行
```bash
python /mnt/skills/public/xlsx/recalc.py model.xlsx
```
エラーなしで成功を返す必要があります。

<a id="section-balancing"></a>
### セクションのバランス調整
- [ ] バランスをとる必要があるセクション (資金調達／使途、資産/負債) のバランスが正確に一致していること
- [ ] プラグ項目はバランス数値として正しく計算されます
- [ ] セクション間で一致するはずの金額が一貫している

<a id="incomeoperating-projections"></a>
### 利益・営業見通し
- [ ] 原動力または成長率から収益/トップラインを正しく構築する
- [ ] すべての費用および経費項目は適切に計算されます
- [ ] 小計と合計が正しく合計される
- [ ] マージンと比率が妥当である
- [ ] 仮定へのリンクは正しいです

<a id="balance-sheet-if-applicable"></a>
### 貸借対照表 (該当する場合)
- [ ] 資産 = 負債 + 資本 (バランスが必要)
- [ ] すべてのアイテムは適切なスケジュールまたはロールフォワードにリンクされます
- [ ] 期首残高 = 前期間の期末残高
- [ ] チェック行を含め、その値がゼロであることを確認します

<a id="cash-flow-if-applicable"></a>
### キャッシュ フロー (該当する場合)
- [ ] 正しい収入額から始める
- [ ] 現金以外の項目は適切に加算/減算されます
- [ ] 運転資本の変化には正しい符号がある
- [ ] 期末キャッシュ = 期首キャッシュ + 純キャッシュフロー
- [ ] 現金残高は明細書全体で一貫しています

<a id="supporting-schedules"></a>
### サポートスケジュール
- [ ] ロールフォワードスケジュールバランス (開始 + 変更 = 終了)
- [ ] スケジュールはメインステートメントに正しくリンクされています
- [ ] 計算項目は適切なドライバーを使用します
- [ ] すべての期間が一貫して計算されます

<a id="debtfinancing-schedules-if-applicable"></a>
### 借金/資金調達スケジュール (該当する場合)
- [ ] 期首残高はソースまたは前の期間に関連付けられます
- [ ] 利息は適切な残高に基づいて計算されます（通常は開始時）
- [ ] 支払いは現金の利用可能性と優先順位を考慮します
- [ ] 期末残高をマイナスにすることはできません
- [ ] トランシェの合計を正しく合計します

<a id="returnsoutput-analysis"></a>
### 投資リターン／出力の分析
- [ ] 出口/終端値が正しく計算されました
- [ ] 関連するすべての調整が含まれています
- [ ] キャッシュフローの符号は正しい (投資はマイナス、回収額はプラス)
- [ ] IRR/MOIC 式は完全な範囲を参照
- [ ] 結果はシナリオに対して妥当です

<a id="sensitivity-tables-if-applicable"></a>
### 感度テーブル (該当する場合)
- [ ] グリッドの寸法は奇数 (5×5 または 7×7) です - 真の中央セルがあります
- [ ] 行軸と列軸の値は、基本ケース (`[base-2Δ, base-Δ, base, base+Δ, base+2Δ]`) に対して対称です。
- [ ] 中央セルの出力はモデルの実際の IRR/MOIC と等しくなります — テーブルが正しく配線されていることを確認します
- [ ] 中央のセルが強調表示されます (中青の塗りつぶし `#BDD7EE`、太字フォント)
- [ ] 行ヘッダーと列ヘッダーには適切な入力値が含まれます
- [ ] 各データ セルには数式が含まれています (ハードコードされていません)。
- [ ] 各データセルには異なる値が表示されます
- [ ] 値は予想される方向に移動します (より高いエグジット倍率 → より高い IRR など)

<a id="formatting"></a>
### 書式設定
- [ ] ハードコードされた入力は青色 (0000FF)
- [ ] 計算式は黒（000000）
- [ ] 同じタブのリンクが紫色になる (800080)
- [ ] タブ間リンクは緑色 (008000)
- [ ] すべての数値は右揃えです
- [ ] 全体に適用される適切な数値形式
- [ ] エラー値 (#REF!、#DIV/0!、#VALUE!、#NAME?) が表示されるセルはありません。

<a id="logical-sanity-checks"></a>
### 論理的健全性チェック
- [ ] 数値は妥当な桁数です
- [ ] トレンドは理にかなっています (予想通りの成長、衰退、安定)
- [ ] 明らかに間違った値はありません (正であるべきところが負である、不可能なパーセンテージなど)
- [ ] 主要な出力は分析の種類に対して妥当な範囲内にある

## 避けるべき一般的なエラー

| エラー | 何が間違っているのか | 修正方法 |
|-------|-----------------|------------|
| 計算された値をハードコーディングする | 入力が変更されてもモデルが更新されない | ソースセルを参照する数式を常に使用してください |
| コピー後の間違ったセル参照 | 数式が間違ったセルを指している | すべてのリンクを確認し、適切な $ アンカーリングを使用してください |
| 循環参照エラー | モデルは計算できません | 金利タイプの計算には期首残高を使用し、循環参照を解消します |
| セクションのバランスが取れていない | 一致するはずの合計が一致しない | 1 つのアイテムがプラグであることを確認します (差異として計算されます) |
| 不可能な場合のマイナス残高 | 利用可能額を超える支払い/使用 | MAX(0, ...) または MIN 関数を適切に使用する |
| IRR/リターンエラー | 間違った符号または不完全な範囲 | キャッシュフローの符号を確認し、計算式がすべての期間をカバーしていることを確認します |
| 感度表も同じ値を示します | 入力によって式が変化しない | セル参照を確認します - 混合参照が必要です ($A5、B$4) |
| ロールフォワードは結びつかない | 始まり≠前の終わり | 期間間のリンクを検証する |
| 一貫性のない符号規則 | 足し算が引き算になる、またはその逆になる | 全体を通して一貫してテンプレートの規則に従います |

## ユーザーとの連携 - セクションごとのチェックポイント

* **テンプレートの構造が不明瞭な場合**、続行する前に質問してください。
* **ユーザーの要件がテンプレートと矛盾する場合**、ユーザーの設定を確認してください
* **各主要セクションを完了したら**、続行する前に停止してユーザーに確認してください。
  - **資金調達・使途後** → バランスの取れたテーブルを表示し、プラグが正しいことを確認し、オペレーティング モデルを構築する前に承認を得ます。
  - **運用モデル/予測後** → 予測損益を表示し、成長率とマージンが適切であることを確認し、債務スケジュールの前に承認を得ます。
  - **債務スケジュール後** → 開始/終了残高と利息を表示し、ウォーターフォール ロジックを確認し、投資リターン前に承認を得ます
  - **投資リターン後 (IRR/MOIC)** → キャッシュ フロー シリーズと出力を表示し、符号と範囲を確認し、感応度テーブルの前にサインオフを取得します。
  - **感度テーブルの後** → 各セルが変化することを示し、基本ケースが予想どおりに到達することを確認します。
* **検証中にエラーが見つかった場合**、次のセクションに進む前に修正してください。
* **作業内容を示す** - 重要な公式や仮定が役立つ場合は説明します
* **各セクションでチェックインせずに完成したモデルを決して提示しないでください** - 壊れた IRR から逆に追跡するよりも、ソースで間違ったセル参照を見つけた方が早いです。
