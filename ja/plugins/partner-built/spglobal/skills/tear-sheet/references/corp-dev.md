# 経営企画・M&A担当向け企業要点資料

<a id="purpose"></a>
## 目的
買収の可能性を評価する社内の経営企画・M&A担当チームの目標評価プロファイル。 IB/M&A プロファイル (ピッチの戦略的な *ストーリー* を伝える) とは異なり、これは戦略的適合性、つまりターゲットの製品、顧客、テクノロジー、および業務が買収者の製品とどのように重複するか、または補完するかに焦点を当てた分析文書です。 Corp Dev の聴衆はすでに自分の会社を知っています。「これを購入すべきか、統合はどのようになるか?」というレンズを通してターゲットを理解する必要があります。

**デフォルトのページ長:** 1 ～ 2 ページ。経営企画・M&A担当チームは、より密度の高いプロファイルに慣れており、コンテンツが実質的であれば 2 ページ目にペナルティを課すことはありません。

<a id="query-plan"></a>
## クエリプラン

これらのクエリから始めてください。結果が不完全な場合は分解してフォローアップします。

**クエリ 1 — ターゲット プロファイル:**
「[会社] 事業内容 製品サービス 技術プラットフォーム 本社設立 従業員部門 業界」
→ ヘッダー、事業・製品概要
→ **すぐに** `/tmp/tear-sheet/company-profile.txt` に書き込みます

**クエリ 2 — 財務:**
「[会社] 年間損益計算書 売上総利益 EBITDA 営業利益 純利益 設備投資 フリー キャッシュ フロー 研究開発費 過去 4 会計年度の負債総額 現金および同等物」
→ 財務概要 (4 年を抽出し、3 を表示。前年比成長率の計算には最も早い年のみを使用します。研究開発は経営企画・M&A担当にとって特に重要です。企業は、ターゲットの IP への投資を理解したいと考えています)
→ **生の値をすぐに** `/tmp/tear-sheet/financials.csv` に書き込みます

**クエリ 3 — セグメント + 顧客:**
「[会社] 過去 2 会計年度のセグメント ビジネス ユニット別の収益 主要顧客 エンド マーケット 顧客集中度」
→ 収益構成（前年比成長には2年必要）、顧客分析
→ **ただちに** セグメント データを `/tmp/tear-sheet/segments.csv` に書き込みます (セグメント データが返されない場合はスキップします)

**クエリ4：取引関係と競争環境**
「[会社] 主要顧客、サプライヤー、パートナー、競合他社、ビジネス関係、テクノロジー ベンダー」
→ 戦略的フィット分析、エコシステムマップ
→ **すぐに** `/tmp/tear-sheet/relationships.txt` に書き込みます

**クエリ 5 — 評価 + ピア:**
ユーザーが特定のコンプを提供した場合:
「[競合企業] 企業価値 EV/収益 EV/EBITDA 収益成長率 EBITDA マージン」
それ以外の場合:
競合企業ツールで上場同業他社を3〜5社特定し、各社のEV/Revenue（NTM）、EV/EBITDA（NTM）、売上成長率%、EBITDA利益率%を取得します。
また: 「[会社] 企業価値時価総額評価倍率」
→ 評価コンテキスト
→ **会社の倍数を `/tmp/tear-sheet/valuation.csv` に直ちに書き込みます**
→ **すぐにピアデータを `/tmp/tear-sheet/peer-comps.csv` に書き込みます**

**クエリ6：持分構成（データを取得できる場合）**
「[会社] 所有権構造 投資家 機関投資家所有権 インサイダー所有権」
→ 所有権スナップショット (中間ファイルなし - 利用可能な場合は company-profile.txt に含まれます)

<a id="sections"></a>
## セクション

優先順にリストされています。明示的なカットのガイダンスについては、以下の「ページの予算とカット順序」を参照してください。

<a id="1-company-header"></a>
### 1. 会社のヘッダー
IB/M&A に似ていますが、「戦略的関連性」というキャッチフレーズが追加されています。

| フィールド | 注意事項 |
|---|---|
| 会社名 | 大きくて大胆な |
| ティッカー・取引所 | 上場企業のみ。非上場企業は省略 |
| 本社所在地 | |
| 設立・従業員数 | |
| 企業価値（Enterprise Value） | 上場企業は時価総額、非上場企業は直近の評価額 |
| 持分・経営体制 | 上場／PE出資／創業者主導等 |
| **戦略的関連性** | 一文: このターゲットが買収者にとって魅力的な理由 (データから総合) |

「戦略的関連性」ラインは Corp Dev に固有のものです。ターゲットのマーケティング言語ではなく、中立的な分析の観点から書きます。ターゲットが*である*ものではなく、取得者が*取得する*ものをフレーム化します。良い点: 「規制堀と 70% 以上の粗利を備えた商品価格ベンチマークにおける支配的な地位。資本が少なく、障壁の高いデータ資産。」悪い例: 「金融データと分析の世界有数のプロバイダー。」前者は、経営企画・M&A担当チームにこれが魅力的な理由を伝えます。後者はプレスリリースです。

<a id="2-business--product-overview"></a>
### 2. 事業・製品概要
**CIQ の会社概要を貼り付けないでください。** 製品とテクノロジーに焦点を当てて 4 ～ 6 文 (2 段落ではなく 1 段落) で書き直してください。この読者は投資ではなく買収を評価します。
- 主要な製品/サービスとそれらが解決する問題
- テクノロジーまたはプラットフォーム アーキテクチャ (高レベル)
- 主要な差別化要因と競争堀
- 顧客セグメント — 誰がなぜこれを購入するのか
- 現在の戦略的方向性

取得者のレンズを使って書きます。読者は次のように考えます。「これは私たちがすでに持っているものとどのように適合するでしょうか?」説明では、重複や補足を簡単に見つけられるようにする必要があります。

<a id="3-revenue-mix--customer-profile"></a>
### 3. 収益構成と顧客プロファイル
2 つのサブセクション:

**a) セグメント別の収益** (可能な場合):

| セグメント | 収益 (百万ドル) | 全体の % | 前年比成長率 |
|---|---|---|---|

**b) 顧客分析:**
セグメント表の下 (またはセグメントが使用できない場合はその代わり) に、次の内容をカバーする定性的な段落を書きます。
- 顧客の集中度: 上位 5 つの顧客は収益の 30% を超えていますか? (買収リスクにとって重要)
- 顧客のタイプ: エンタープライズ vs. SMB vs. 一般消費者
- 契約構造: サブスクリプション、トランザクション、ライセンス (既知の場合)
- 地理的混在

ここで最も重要なシグナルは顧客の集中度です。ツールが上位顧客または収益の集中度に関するデータを返した場合は、それを目立つように強調表示します。データがまばらな場合は、ビジネスの説明と関係から推測できることを書きます。これは 2 ～ 3 文にとどめてください。これはセグメント テーブルのコンテキストであり、独立した分析ではありません。

<a id="4-strategic-fit-analysis"></a>
### 4. 戦略的適合分析
**この要点資料の特徴となる主要セクションです。** 必須なので省略・圧縮してはいけません。S&P Capital IQの取引関係データを使い、重複と補完関係を整理します。

3つのバケツとして整理します。 **各バケットは、企業名のリストではなく、2 ～ 3 文の分析推論である必要があります。** 文脈なしに「顧客: Microsoft、JPMorgan、Google」をリストするのは役に立ちません。代わりに、取得に関して*重複または補完が何を意味するか*を説明してください。

**顧客の重複:** ターゲットの顧客は買収者 (または買収者の業界) からも購入しますか?顧客の共有 = クロスセルが容易になりますが、チャネル競合のリスクも伴います。共有関係に名前を付け、その影響を説明します。

**テクノロジー/製品の補完:** ターゲットは買収者のポートフォリオのギャップを埋めていますか?彼らの技術スタックはどのようなものですか?テクノロジーベンダーは誰ですか?すでに買収者のテクノロジーを使用している場合は、それが強力な統合シグナルである理由を説明してください。

**競合他社の排除:** ターゲットは競合他社ですか? それとも、ターゲットを買収することで競合他社が市場から排除されますか?ターゲットの主要な競合他社の名前を挙げ、買収後に競争環境がどのように変化するかを説明してください。

このセクションでは合成が必要です。関係データとビジネス概要を組み合わせて、関連性を引き出します。ユーザーが取得者を教えてくれた場合は、その取得者に合わせて調整します。そうでない場合は、一般的ではありますが、分析的に記述してください。

**文量の規律：** 各分類2〜3文は提案ではなく厳密な制約です。最初に示唆を述べ、具体的なデータ一件で支えます。実際の出力は一項目5〜7文に膨らみがちで、三ページ目へのはみ出しの主因です。3文を超えたら、余分な詳細を「統合の検討事項」へ移します。

<a id="5-financial-summary-3-year"></a>
### 5. 財務概要（3年間）
IB/M&A に似ていますが、R&D と資本効率がさらに重視されています。

| メトリック ($M) | 20XX年度 | 20XX年度 | 20XX年度 |
|---|---|---|---|
| 収益 | | | |
| 収益成長率 % | | | |
| 粗利率 % | | | |
| EBITDA | | | |
| EBITDAマージン% | | | |
| 研究開発費 | | | |
| 収益に占める研究開発の割合 | | | |
| 設備投資 | | | |
| フリーキャッシュフロー | | | |
| FCF転換率（FCF/EBITDA） | | | |

研究開発の強度は、ターゲットの価値がサービスと比べて知財にどれだけあるのかを示します。 FCF 変換は統合の複雑さを示します。設備投資が高いビジネスは統合が難しくなります。研究開発費が個別に報告されていない場合は、その行に「該当なし」ではなく「個別に開示されていない」と記入してください。これ自体が有益です（研究開発が売上原価や販管費に組み込まれている可能性があることを示唆しています）。

**資本構成** (財務概要の下にあるコンパクトなサブテーブル):

| メトリック | 値 |
|---|---|
| 有利子負債合計 | $XXM |
| 現金および同等物 | $XXM |
| 純負債 | $XXM |
| 純負債/EBITDA | X.Xx |

買収コンテキストのフレーム: 表の下に、レバレッジを解釈する一文を含めます (例: 「$X の純負債は Y.Yx EBITDA レバレッジを表しており、投資適格の買収者にとっては管理可能ですが、LBO シナリオではレバレッジが複合化します。」)。すでに取得されている貸借対照表データから取得します。

<a id="6-valuation-context"></a>
### 6. 評価の背景
**このセクションは上場企業には必須です。** 経営企画・M&A担当チームは潜在的な入札を組み立てるために市場のコンテキストを必要とします。ツールが評価倍数を返す場合、このセクションが表示される必要があります。スペースを確保するためにそれを切り取らないでください。最初に所有権スナップショット (セクション 7) を切り取ります。

正式な評価ではありません。経営企画・M&A担当チームは独自の DCF を作成します。これにより、市場のコンテキストが提供されます。

**a) 取引倍率** (公開の場合):

**ピア コンテキストは必須であり、オプションではありません。** ユーザーがカンプを提供した場合は、それぞれを独自の列に表示します。競合他社が提供されていない場合は、競合他社ツールを使用して 3 ～ 5 社の上場同業他社を特定し、それぞれの EV/収益 (NTM)、EV/EBITDA (NTM)、収益成長率 %、および EBITDA マージン % を取得します。

| メトリック | 【会社】 | [ピア1] | [ピア2] | [ピア3] | ピア中央値 |
|---|---|---|---|---|---|
| EV/収益 (NTM) | | | | | |
| EV/EBITDA (NTM) | | | | | |
| 収益成長率 % | | | | | |
| EBITDAマージン% | | | | | |

企業の倍率だけでは、経営企画・M&A担当チームには何も伝わりません。ターゲットが他のグループと比べて安いのか、それともリッチなのかを評価するには、相対的なコンテキストが必要です。これは、ターゲット プロファイルの最小限の実行可能な評価コンテキストです。

ピアのマルチプルがツールから利用できない場合は、読者の参照のために、会社独自のマルチプルを表示し、選択したピアの名前を表の下にリストします。

**b）類似取引事例（データを取得できる場合）**
M&A ツールが会社の同業他社または同じサブセクター内の最近の取引を返した場合は、それらを表示します。

| 日付 | 対象企業 | 買収企業 | EV（$M） | EV/売上高 | EV/EBITDA |
|---|---|---|---|---|---|

背景として、「[サブセクター]の直近の取引では、対象企業は売上高のX〜Y倍で評価された」と示します。

前のトランザクション データがツールから利用できない場合は、黙って省略するのではなく、「前のトランザクション データがデータ ソースから利用できない」ことに注意してください。前例の倍数を捏造しないでください。

非上場企業の場合は、取引倍率を省略してください。類似取引事例 (データを取得できる場合) は引き続き役に立ちます。

<a id="7-ownership-snapshot-data-permitting--omit-if-tools-return-nothing"></a>
### 7. 所有権のスナップショット (データを取得できる場合、ツールが何も返さない場合は省略します)
ツールが所有権データを返す場合は、創設者/家族の支配率、PE スポンサーの詳細、機関の集中度などのコンパクトなブロックを含めます。所有構造は取引の複雑さに直接影響し、統合の検討に関連します。

**経営チームのテーブルは含めないでください。** S&P Global ツールはエグゼクティブ データを返しません。データ整合性ルール 10 を参照してください。トレーニング データからの経営陣名は古くなります。

<a id="8-integration-considerations"></a>
### 8. 統合に関する考慮事項
**必須セクション — 切り取らないでください。** これは、Corp Dev 企業要点資料の分析の要点です。上記のすべてから得られた総合的な観察。 3 ～ 4 つの重要な箇条書き:
- **主なリスク:** 顧客の集中、キーパーソンへの依存、テクノロジー負債の指標
- **統合の複雑さ:** 地理 (複数の国 = 難しい)、従業員数、製品の数
- **相乗効果のシグナル:** 共通の顧客、補完的な製品、重複するテクノロジー ベンダー
- **未解決の論点：** 買収提案前に必要なデューデリジェンスは何か。広い戦略的質問ではなく、実行可能な確認項目に絞ります。良い例は、規制承認の時期・法域、主要契約の支配権変更条項、創業者・CTO等の引留めリスク、顧客契約の譲渡可能性、知財の帰属、係争中の訴訟です。「Xの競争優位はどれほど持続可能か」「長期の市場機会は何か」は分析者向けの問いで、具体的な調査項目ではありません。

データ ソースからの事実ではなく、分析的な観察であることを明確にラベル付けします。

<a id="page-budget--cut-order"></a>
## ページ予算とカットオーダー

**目標は2ページ。** 中身があれば両ページを使えますが、ユーザーが長い版を明示的に求めない限り三ページ目へ進みません。超えたら次の順で削り、一項目を完全に処理してから次へ進みます。

1. 所有権のスナップショット (セクション 7) — 完全に省略
2. 収益構成に関する顧客分析の散文 (セクション 3) — 最大 2 文に減らす
3. 評価コンテキスト散文 (セクション 6) — ピア比較表を保持し、その下の解釈段落をカット
4. 類似取引事例 (セクション 6b) — 「利用できません」というメモを残し、スペースが重要な場合は削除します
5. 資本構造の散文 — 表を保持し、その下の解釈の段落をカットします
6. 戦略的適合分析 (セクション 4) — 各箇条書きを最大 2 ～ 3 文に圧縮します (セクションは削除しないでください)。

絶対に削らない節：事業・製品概要（2）、財務概要の主要表（5）、統合の検討事項（8）。

<a id="formatting-notes"></a>
## メモのフォーマット
- **戦略的フィット分析が中心です。** 独特の書式設定を行います。
  - テキストを 9.5pt (サイズ: 19) にバンプします。標準の本文テキストよりわずかに大きくなります。このセクションは、ページ上で最も重要なコンテンツのように見えるはずです。
  - グローバル スタイル設定の標準のインデントされたブロック スタイルの箇条書きを使用します (360 DXA 左インデント)。
  - 左境界線のアクセントを適用しないでください。docx-js でのレンダリングに一貫性がありません。
- 財務概要には、研究開発と FCF 変換を目立つように含める必要があります。
- 上場企業には、同業他社との評価コンテキストが必要です。所有権スナップショットの前にカットしないでください。
- 非公開ターゲットの場合、プロファイルは定性的なセクション (ビジネスの概要、戦略的適合性、取引関係) に大きく依存しています。これは予想されることであり、依然として非常に価値があります。
- 口調: 分析的かつ評価的であり、宣伝的ではありません。これは売り込みではなく、評価です。
- **2 ページの規律:** レンダリングする前に、ページ数を頭の中で見積もります。 Strategic Fit (3 つの長い箇条書き) + 統合に関する考慮事項 (4 つの箇条書き) の組み合わせだけでも、ページ全体を消費する可能性があります。その場合は、最初に Strategic Fit の箇条書きを圧縮します。
