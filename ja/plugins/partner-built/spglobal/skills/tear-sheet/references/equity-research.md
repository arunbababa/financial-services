# 株式調査向け企業要点資料

<a id="purpose"></a>
## 目的
投資を評価するバイサイドまたはセルサイドのアナリスト向けの詳細なスナップショット。バリュエーション、将来予測、財務軌跡、アナリストのコンセンサスを重視します。すべてが投資理論を支持するか、または疑問を投げかけます。

**デフォルトのページ長:** 1 ページ。株式調査の企業要点資料は従来は 1 ページであり、重要なのは密度です。ユーザーがさらに多くのスペースを要求した場合は、2 ページまで拡張します。

<a id="query-plan"></a>
## クエリプラン

これらのクエリから始めてください。結果が不完全な場合は、より狭い範囲のフォローアップに分けてください。

**クエリ 1 — プロファイル + 市場データ:**
「【会社】会社概要 セクター 業種 時価総額 企業価値 株価 52週高値・安値 発行済株式数ベータ」
→ ヘッダー、事業内容
→ **すぐに** `/tmp/tear-sheet/company-profile.txt` に書き込みます

**クエリ 2 — 過去の財務状況:**
「[会社] 年間損益計算書 売上総利益 EBITDA 純利益 EPS フリー キャッシュ フロー 過去 4 会計年度の負債総額 現金および同等物」
→ 財務概要 (4 年を抽出、3 を表示、前年比成長率の計算には最も早い年のみを使用)
→ **生の値をすぐに** `/tmp/tear-sheet/financials.csv` に書き込みます

**クエリ 2b — セグメント (利用可能な場合):**
「[会社] 過去 2 会計年度のセグメント事業単位別の収益」
→ 収益とセグメントの内訳 (前年比成長には 2 年必要)。セグメント データが利用できない場合は、このセクションをスキップしてください。テーブルを空白のままにしないでください。
→ **ただちに** `/tmp/tear-sheet/segments.csv` に書き込みます (セグメント データが返されない場合はスキップします)

**クエリ 3 — 評価 + コンセンサス:**
「[企業] P/E EV/EBITDA EV/収益評価倍率コンセンサス収益 EPS 推定アナリスト推奨価格目標」
→ 評価スナップショット、コンセンサス推定
→ **ただちに**倍数を `/tmp/tear-sheet/valuation.csv` に書き込みます
→ **すぐに見積もりを** `/tmp/tear-sheet/consensus.csv` に書き込む

**クエリ 4 — 収益:**
「[会社] 最新の決算発表の重要なポイント ガイダンス」
→ 決算ハイライト
→ **すぐに** `/tmp/tear-sheet/earnings.txt` に書き込みます

**クエリ 5 — 株式パフォーマンス:**
「[会社] 株価リターン 1 か月、3 か月、6 か月、1 年間の年初来パフォーマンス」
→ ストックパフォーマンス (中間ファイルなし - データは直接ドキュメントに入力されます)

**クエリ 6 (ユーザーがカンプを提供した場合):**
「[競合企業] 時価総額 EV/収益 EV/EBITDA 収益成長率」 — 競合ごとに繰り返します
→ 評価スナップショットのピアコンテキスト
→ **すぐに** `/tmp/tear-sheet/peer-comps.csv` に書き込みます

<a id="sections"></a>
## セクション

優先順にリストされています。 1 ページに制限されている場合は、下からカットします。

<a id="1-company-header"></a>
### 1. 会社のヘッダー
グローバル スタイル設定に従って 2 列のボーダーレス テーブルとしてレンダリングされるコンパクトなキーと値のブロック。

左列: ティッカー (取引所)、セクター/業界、本社
右列: 株価、52週間レンジ、時価総額、EV、発行済株式数、ベータ

<a id="2-business-description"></a>
### 2. 事業内容
2、3 のタイトな文。 **アナリスト向けに自分の言葉で書き直してください** — CIQ の企業概要をそのまま貼り付けないでください。 CIQ サマリーは入力です。出力は簡潔で投資仮説に沿ったである必要があります。

広く知られ、広く取り上げられている企業の場合、アナリストは基本的なビジネスをすでに知っていると想定します。ウィキペディア形式の概要ではなく、戦略的転換、ポートフォリオの再構築、新たな成長ベクトルなど、*変化* しているものを中心にリードします。たとえば、フォーチュン 500 企業の場合、「金融データを機関に提供する」ということに一文も費やさないでください。代わりに、「保留中のモビリティのスピンオフと、Kensho 子会社を通じた積極的な AI 投資により、収益性の高いデータおよび分析ビジネスに向けてポートフォリオを再構築する。」

あまり知られていない企業の場合は、投資仮説関連のダイナミクスに焦点を当てる前に、「自社が何をしているか」という短い文が適切です。

<a id="3-valuation-snapshot"></a>
### 3. 評価スナップショット
株式企業要点資料の目玉。

| メトリック | トレーリング | フォワード(NTM) |
|---|---|---|
| P/E | | |
| EV/EBITDA | | |
| EV/収益 | | |
| P/FCF | | |
| 配当利回り | | |

**ツールから取得できるなら、将来予想の倍率は必須です。** 予想データがあるのに実績倍率だけでは大きな不足です。アナリストは将来利益に基づき企業を評価します。予想倍率を取得できなければ実績だけを示し、「Fwd estimates N/A」と注記します。

ユーザーが比較可能な企業を指定した場合は、各企業の列を追加します (または、3 つ以上の企業の場合は「ピア中央値」列)。ユーザーがカンプを作成せず、ツールがピア データを返す場合は、ピア中央値列を含めます。どちらでもない場合は、会社の倍率のみを表示します。

<a id="4-consensus-estimates"></a>
### 4. コンセンサス推定
市場アナリストが何を予想しているかを示します。この種類の要点資料の重要な特徴です。

**データの利用可能性に関する注意:** コンセンサス データの深さは企業や対象範囲によって異なります。アナリスト数、目標株価、買い/保有/売りの分布など、ツールが返すものはすべて含めますが、コンセンサス数値を捏造したり推定したりしないでください。対象範囲が薄い企業の場合、このセクションには収益と EPS の見積もりの​​みが含まれる場合がありますが、それでも価値があります。

| メトリック | 年度[年] 予想 | 会計年度[年+1]予想 |
|---|---|---|
| 収益 | | |
| EPS (正規化) | | |
| EBITDA | | |

利用可能な場合は正規化/調整された EPS を使用します。GAAP EPS は一時的な項目によって歪められる可能性があり、将来の推定にはあまり役に立ちません。

主要な推定値の表の下に、コンパクトなアナリストのコンセンサス ブロックを含めます (データがツールから入手可能な場合)。

| アナリストのコンセンサス | |
|---|---|
| 平均目標株価 | $XXX |
| 予想件数 | XX |
| 買う / 保有する / 売る | XX / XX / XX |

価格目標または推奨データが利用できない場合は、空の行を表示するのではなく、アナリストのコンセンサス ブロックを省略します。これらの数字を捏造しないでください。

コンセンサス データがまったく利用できない場合は、このセクション全体をスキップして、「コンセンサス推定値が利用できない」ことに注意してください。推定しないでください。

| メトリック ($M) | 20XX年度 | 20XX年度 | 20XX年度 |
|---|---|---|---|
| 収益 | | | |
| 収益成長率 % | | | |
| 粗利率 % | | | |
| EBITDA | | | |
| EBITDAマージン% | | | |
| 当期純利益 | | | |
| EPS（希薄化） | | | |
| フリーキャッシュフロー | | | |
| 純負債 | | | |

個別にクエリを実行するのではなく、生データから派生指標 (成長率、マージン) を計算します。

**資本構成 (財務概要の下にある別のコンパクトなサブテーブル):**
これらの行を 3 年間の財務概要表に追加しないでください。前年の列の空白セルはデータが欠落しているように見えます。代わりに、別個の 2 列のサブテーブル (メトリック | 値) をそのすぐ下に表示し、最新の会計年度のみを表示します。

| メトリック | 年度[最新] |
|---|---|
| 有利子負債合計 | $XXM |
| 現金および同等物 | $XXM |
| 純負債 | $XXM |

これは、Corp Dev および IB/M&A 企業要点資料で使用される資本構成形式と一致します。財務概要とこのサブテーブルの間に余分なスペースを入れないでください。

<a id="6-revenue--segment-breakdown"></a>
### 6. 収益とセグメントの内訳
ツールからセグメント データを入手できる場合は、コンパクトなセグメント収益表を含めます。これは株式調査にとって重要なコンテキストです。アナリストはどの事業分野が成長を推進しているのかを確認する必要があります。

| セグメント | 収益 (百万ドル) | 全体の % | 前年比成長率 |
|---|---|---|---|
| 【セグメントA】 | | | |
| 【セグメントB】 | | | |

概要資料としてコンパクトにまとめます。表のみで、定性的な段落はありません。セグメント データが利用できない場合は、このセクションを完全にスキップしてください。空のテーブルやプレースホルダー テーブルは含めないでください。

<a id="7-recent-earnings-highlights"></a>
### 7. 最近の業績ハイライト
四半期と日付を含めます (例: 「2025 年度第 3 四半期 — 2025 年 10 月」)。 **投資レンズ**を使用した 3 ～ 4 つの箇条書き — この視聴者は戦略的なテーマではなく、セグメント レベルの詳細を求めています。

**ガイダンスが提供されている場合は、そのガイダンスを示します。** 経営陣がフォワード ガイダンスを発行した場合は、最初の箇条書きに太字の **ガイダンス:** という接頭辞を付けます (例:「**ガイダンス:** 2026 年度の EPS は 19.40 ～ 19.65 ドルで、9 ～ 10% の成長を意味し、本業収益の成長は 6 ～ 8% である。」)。ガイダンスは、アナリストにとって最も実用的な将来予測データ ポイントです。これを営業ハイライトの中に埋め込まないでください。

**コンセンサスの上振れ・下振れ（データを取得できる場合）：** 対象期のコンセンサス予想があれば、「売上高$Xはコンセンサス$YをZ%上回った／下回った」と主要結果を示します。ツールからその期のコンセンサスを得られなければ、実績の絶対値と成長率だけで説明し、予想値を捏造してはいけません。

次に:
- セグメントレベルの業績: どの事業分野が加速または減速したか
- 利益率の推移: コスト構造または収益性の傾向に関するコメント

経営陣への帰属: 宣言的な主張ではなく、「経営陣が強調した…」または「CFO が注目した…」。このセクションは、プレスリリースの概要ではなく、収益の概要のように感じてください。

<a id="8-key-operating-metrics"></a>
### 8. 主要な運用指標
データから入手可能な場合は、2 ～ 3 つのセクター関連の KPI (加入者数、既存店売上高、NIM など)。セクター固有のものがない場合は、既に取得した財務データから ROE と ROIC を計算します。オプション — スペースが狭い場合はドロップします。

<a id="formatting-notes"></a>
## メモのフォーマット
- **これは最も密度の高い企業要点資料 タイプです。** 他のテンプレートよりも明らかに圧縮されているように感じられます。
- 財務概要表: 8 ポイントのテキスト (サイズ: 16)、行の高さ 240 DXA。あらゆるテンプレートの中で最も狭い間隔。
- 評価スナップショットとコンセンサス推定: 8.5 ポイントのテキストが視覚的な中心を占めます。アナリストは最初にこれらをスキャンします。
- 本文テキスト: 8.5pt (サイズ: 17) — グローバルのデフォルトの 9pt よりも小さい。概要資料ではすべてのハーフポイントが重要です。
- セクション間隔: 最小化します。セクションヘッダーの前に 6 ポイント (グローバルな 12 ポイントではありません)、ルールの後に 2 ポイント。
- 顕著な変曲（成長がプラスに転じる、マージンの拡大/縮小）を示す指標を太字にします。
- あらゆる場面で空白よりも情報を優先します。
