<a id="portfolio-ai-readiness"></a>
# 投資先全体のAI活用準備の評価

<a id="workflow"></a>
## ワークフロー

<a id="step-1-connect-to-portfolio-data"></a>
### 手順1：投資先のデータへ接続する

最初に資料の保存先を尋ねる。決めつけず、選択肢を示す。

- **MCPサーバー：** 接続済みなら、データルーム、SharePoint、Google Drive、投資先運営データベース。
- **ローカルファイル：** 四半期スライド、財務、取締役会資料のあるディスク上のフォルダー。
- **アップロード：** PDF、PowerPoint、Excelを会話へ直接添付。

接続後、投資先全体または一部の四半期報告、取締役会スライド、財務を取得する。各社のセクター、売上、職能別人員、言及された技術構成、進行中のAI・自動化施策を抽出する。

1社だけ指定された場合も調べるが、企業横断順位付けは省く。

資料から明らかでなければ最初に尋ねる。
- 各社の残り保有期間（売却12か月前ではAIの投資回収の重要性は下がる）
- 既に何らかの施策を導入して成果が出た会社があるか

<a id="step-2-per-company-scan"></a>
### 手順2：会社別の調査

各社に3つの可否条件を問う。全部「はい」なら **Go（実行）**、1つでも「いいえ」なら **Wait（保留）** とし、何が解決すれば進めるかを記す。

1. **データはあるか。** 顧客一覧、請求書データ、契約保管庫など、用途に合う整った入力を、先に6か月のデータ整備を行わず作れるか。
2. **責任者はいるか。** 「支援する」だけの後援者でなく、経営陣の中で推進する人がいるか。
3. **30日で試行できるか。** 1チーム・1業務・既製ツールで始められるか。「まず……が必要」となるなら短期間の成果ではない。

次に効果の大きい上位2〜3のポイントを探す。費用構造・業務の次のパターンを見る。

**バックオフィス（通常、最も速く試せる）**
- 請求書処理、買掛・売掛照合、経費分類
- 契約の要点抽出：業者契約、賃貸借、顧客基本契約
- 月次決算：照合、変動要因説明、貸し手向け報告の初稿

**売上・フロントオフィス**
- RFP・提案書の初稿。プロジェクト型売上なら効果が大きい
- 営業通話要約、CRMデータ整備
- 問い合わせチケット分類、初回返信案
- 構成指定型・複雑な製品の見積もり

**業務運営（セクター依存）**
- 標準作業手順・品質文書の生成
- スケジュール・配車（現場サービス・物流）
- コード生成・レビュー（ソフトウェア投資先）

各ポイントを1行で、置き換える作業、週当たり削減できる常勤換算の作業時間（100%でなく30〜50%を仮定）、既製品購入か小規模開発かを示す。

<a id="step-3-rank-across-the-portfolio"></a>
### 手順3：投資先全体で順位付けする

全社の全機会を1つの一覧へ積み上げ、次で順位付けする。

1. **金額効果：** 年換算EBITDAへの寄与（費用削減＋売上増からツール費を控除）。
2. **価値実現の速さ：** 最初に測定できる成果までの月数。
3. **確率：** データ品質、変革管理リスク、経営陣の能力に応じて割り引く。

同順位なら残り保有期間18か月未満の機会を優先する。今動くか、やらないかだからである。

<a id="step-4-find-the-replays"></a>
### 手順4：横展開できる成功パターンを探す

1つの成功策を複数社で実行するのが、投資先全体で最も効果が大きい。次を探す。

- **同セクター・同職能：** 医療サービス2社が手動で事前承認を処理しているなら、1つの実装を2社へ展開する。
- **同ツール・別企業：** ある会社の請求書処理が既に機能しているなら、買掛処理額が年Xmドル超の他社を早期追随候補として示す。
- **共通業者との交渉力：** 同ツールを3社が買うなら、価格交渉の機会になる。

各パターンに、実証する先行企業と、まねる後続企業を付ける。

<a id="step-5-output"></a>
### 手順5：出力

投資先レビューに使う、オペレーティング・パートナー向け1ページ：

1. **全体上位5件：** 手順3の順位表に責任者・30日以内の第一歩を付ける。
2. **横展開：** 複数社へ同時適用できる2〜3の実行手順。
3. **会社別Go／Wait：** 各1行。保留には解消条件。
4. **実施しないこと：** 紙上では良さそうでも可否条件で落ちた機会。四半期ごとに同じ議論を蒸し返さないため。
5. **EBITDA寄与合計：** 全社のAI機会を、1年目の短期成果と2〜3年目の拡大へ分ける。

<a id="important-notes"></a>
## 重要事項

- **興奮度でなく金額で順位付けする。** 売上4,000万ドルの会社で40万ドルを節約する地味な買掛自動化は、華やかな顧客向けチャットボットに常に勝る。
- **実際の制約はほぼ常にモデルでなくデータである。** 整った顧客一覧を作れないなら、最初はAIでなくデータ整備だと明言する。
- **既製品を優先する。** 開発力が弱い会社にとって独自開発は遅く、高く、壊れやすい。購入・導入できるものを優先する。
- **責任者こそ実際の関門。** 内部責任者がない短期施策は90日で立ち消える。経営陣に望む人がいなければ、金額にかかわらずWaitにする。
- **保有期間が緊急性を決める。** 売却3年前なら基盤データ整備ができる。12か月後ならCIMのLTM EBITDAに現れるものが必要で、無理なら省く。
- **失敗した試行も情報である。** 既に試して定着しなかったなら、同案を再提案する前に理由を調べる。
