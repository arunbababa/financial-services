<a id="-critical-rendering-limitation"></a>
## ⚠️ クリティカルなレンダリング制限

**LibreOffice は検証に使用されますが、PowerPoint ファイルを正確にレンダリングしません。** フォント、グラデーション、図形の位置、テキストの折り返し、および一部の表の書式設定が破損します。

**これが意味すること:** LibreOffice でビジュアル検証に合格したスライドでも、Microsoft PowerPoint では問題が残る可能性があります。検証ループは構造的な問題 (コンテンツの欠落、テーブルの破損、プレースホルダーの書式設定の保持) を検出しますが、フォントの置換、微妙な配置のずれ、またはグラデーションの問題は**検出できません**。

**必要なアクション:** 出力を配信するときは、必ず次のステートメントを含めてください。
> 「このファイルは LibreOffice を使用して検証されました。レンダリングの違いが存在する可能性があるため、配布する前に Microsoft PowerPoint で確認してください。」

<a id="template-population-workflow"></a>
## テンプレートへの入力ワークフロー

コピーして進行状況を追跡します。

```
Pitch Deck Progress:
- [ ] Phase 1: Extract and validate source data
- [ ] Phase 2: Map content to template sections
- [ ] Phase 3: Populate slides with proper formatting
- [ ] Phase 4: Validate → Fix → Repeat until clean
- [ ] Phase 5: Final verification
```

<a id="phase-1-data-extraction"></a>
### フェーズ 1: データ抽出
1. 変更を加える前に、元のテンプレートの **バックアップを作成**します — `[filename]_backup.pptx` にコピーします。 XML を直接編集したり、予期しないエラーが発生したりすると、ファイルが破損する可能性があります。
2. すべてのソース資料 (Excel、CSV、PDF レポート、Word ドキュメント、データベース、Web ソース) を特定します。
3. 各ソースから関連するデータポイントを抽出する
4. すべての数値を元のソースと照合して検証する
5. 単位と通貨を標準化します (すべての数値をテンプレートで使用される主な単位/通貨に変換します)
6. 検証が必要な計算に注意してください → 式については [`calculation-standards.md`](reference/calculation-standards.md) を参照してください。

<a id="phase-2-content-mapping"></a>
### フェーズ 2: コンテンツ マッピング
1. **テンプレートを開いて視覚的に確認します** - 変更する前に、その構造、スタイル、既存のコンテンツを理解します。
2. テンプレート構造の分析 — すべてのプレースホルダー領域とコンテンツ ボックスを特定します
3. ソース データを対応するテンプレート セクションにマッピング → マッピングのガイダンスについては、[`slide-templates.md`](reference/slide-templates.md) を参照してください。
4. プレースホルダーのガイダンス ボックス (タスク作成者からの色付きの指示ボックス) を特定します。
5. データのギャップまたは不一致に注意してください → 解決策については、[`slide-templates.md`](reference/slide-templates.md#handling-data-template-mismatches) を参照してください。

<a id="phase-3-template-population"></a>
### フェーズ3：テンプレートへ入力する
1. **プレースホルダー ボックスを削除または再フォーマットします** - 色付きの指示ボックスには、フォーマット方法ではなく、何を作成するかが表示されます。それらを削除し、代わりに適切にフォーマットされたコンテンツを作成します。 [クリティカル アンチパターン](#critical-anti-patterns-never-do-these) を参照してください。
2. 各セクションにマップされたコンテンツを入力します (最初にコンテンツに焦点を当てます)
3. **その後、テンプレート スタイルに一致するように書式設定を適用します** → [`formatting-standards.md`](reference/formatting-standards.md) を参照してください。
4. 実際のテーブル オブジェクトとしてテーブルを作成します (パイプ/タブ区切りのテキストは決して使用しないでください) → [`xml-reference.md`](reference/xml-reference.md#table-implementation) を参照してください。
5. 矢印/図形を PowerPoint オブジェクトとして作成 → [`xml-reference.md`](reference/xml-reference.md#arrow-shapes) を参照
6. タスク ファイルに会社ロゴが指定されている場合は、会社のロゴを挿入します。利用できない場合は、ユーザーにフラグを立てます:「[ロゴが提供されていません - 会社のロゴを提供してください]」

<a id="phase-4-validate--fix--repeat"></a>
### フェーズ 4: 検証 → 修正 → 繰り返し

**これはフィードバック ループです。すべてのチェックに合格するか、エスカレーションがトリガーされるまで繰り返します。**

```bash
# Convert to images for visual validation
soffice --headless --convert-to pdf presentation.pptx
pdftoppm -jpeg -r 150 presentation.pdf slide
```

**検証チェックリスト (各スライド画像を確認してください):**
- [ ] 背景に対してテキストが読めるか?
- [ ] 表は実際のオブジェクトです (パイプ/タブで区切られたテキストではなく、列が整列しています)?
- [ ] チャート/表は指定された領域を埋めていますか?
- [ ] 箇条書きの書式はセクション内で一貫していますか?
- [ ] フォント サイズは同じレベルのボックス間で一致しますか?
- [ ] スライドの境界を越えるコンテンツはありませんか?
- [ ] **プレースホルダーの書式設定は保持されません** (データがダンプされた大きな色のボックスはありません)?
- [ ] **テキストベースの「テーブル」**はありませんか (偽の列を作成する `|` やタブ区切り文字はありません)?
- [ ] **スライド間の一貫性**: 同じ指標/数値が表示されるすべてのスライドで同一ですか?

**修正サイクルプロトコル:**

| サイクル | アクション |
|-------|--------|
| 1 | 特定された問題をすべて修正し、再検証する |
| 2 | 残っている問題を修正し、再検証する |
| 3 | 問題が解決しない場合は、残っている問題を文書化し、ユーザーにエスカレーションします。 |

**3 サイクル後も問題が残る場合:**
1. 未解決の問題をそれぞれスライド番号と説明とともにリストします。
2. 何が試みられたのか説明してください
3. 「次の問題は自動的に解決できませんでした: [リスト]。手動で確認する必要があります。」という明示的な免責事項を付けてファイルを配信します。

**いつまでもサイクリングを続けないでください**。一部の問題 (フォントのレンダリング、複雑な図形の配置) には、PowerPoint での手動介入が必要な場合があります。

<a id="phase-5-final-verification"></a>
### フェーズ 5: 最終検証

納品する前に、[最終品質チェックリスト](#final-quality-checklist) を実行してください。

### フォントの一貫性のマッチング

**同じ階層レベル**のボックスは同じフォント サイズを使用しなければなりません:

| 同じレベル | 一致する必要があります |
|------------|-----------------|
| 「セグメントが含まれる」 | 「除外されたセグメント」 |
| 「定義」 | 「スコープの根拠」 |
| 左列の箇条書き | 右列の箇条書き |
| すべてのブロックのラベル | お互いに |
| すべてのセクションのヘッダー | お互いに |

<a id="rounding-for-presentation"></a>
### プレゼンテーションの丸め込み

これらは **一般的な規則** であり、値の大きさとテンプレート スタイルに基づいて調整します。

| 値のタイプ | 一般的な丸め | 例 |
|------------|------------------|---------|
| 大きな市場規模（100億ドル以上） | 最も近い10億ドル単位 | 18.5 → 190億ドル |
| 市場規模が小さい（100億ドル未満） | 最も近い5億ドルまたは1億ドル単位 | 23億→25億ドル |
| サイズ範囲 | ソースの一致精度 | 14.9-22.1 → 150-220億ドル |
| CAGR | 整数の% または 0.5% | 16.4% → 16% または 16.5% |
| 市場シェア | 最も近い 5% またはソースと一致 | 21.4% → 20% |
| 倍数 | 小数点1 | 9.69 → 9.7x |

**原則:** 四捨五入によって数値が大きく変わることはありません。値が小さい場合は、より細かい精度を使用します。

<a id="text-density-rules"></a>
### テキスト密度のルール

- コンテンツ ボックスごとに最大 6 ～ 7 個の箇条書き
- 箇条書きあたり最大 2 行
- 括弧内の例: 同じ行または下にインデント
- 孤立した単語はありません (改行に 1 つの単語)

<a id="alignment-principles"></a>
### 調整の原則

**垂直に積み上げられたボックス**は以下と同一である必要があります:
- 左マージンの位置、箇条書きのインデント、テキストの開始位置、ボックスの幅

**水平方向に隣接するボックス**は同一である必要があります:
- 上部の位置、高さ（可能な場合）、内部パディング

<a id="multi-slide-consistency"></a>
### マルチスライドの一貫性

同じデータが複数のスライドに表示される場合:
- 同一の図、フォーマット、用語を使用する
- 1 つのスライドで指標が更新された場合は、すべてのスライドが更新されます
- 検証中に相互参照して不一致を検出する

<a id="must-requirements"></a>
## 必須要件

これらの要件は、テンプレートに関係なく交渉の余地がありません。

| 要件 | 詳細 |
|-------------|---------|
| **テキストの読みやすさ** | すべてのテキストは背景と十分なコントラストを持たなければなりません。例: ダークブルー、ダークグリーン、ブラックの背景に白/明るいテキスト。白、ライトグレー、ライトイエローの背景に黒/暗いテキスト。 |
| **実際のテーブル オブジェクト** | 表形式のデータは、タブ区切りのテキストではなく、表オブジェクトである必要があります。 [`xml-reference.md`](reference/xml-reference.md#table-implementation) を参照してください。 |
| **適切なチャート/テーブルのサイズ設定** | 貼り付けたビジュアルは指定された領域を埋める必要があります。 [`formatting-standards.md`](reference/formatting-standards.md#chart-and-image-handling) を参照してください。 |
| **一貫した書式設定** | セクション内の箇条書きは (記号、サイズ、インデント) 一致する必要があります。同じレベルのボックスは同じフォント サイズを使用しなければなりません。 |
| **コンテンツの境界** | すべてのコンテンツはスライドの端内に収まる必要があります。脚注ボックスの幅: 16:9 の場合は ~32.5cm、4:3 の場合は~24cm。 |
| **プレースホルダーの書式設定はありません** | 色付きの説明ボックスを取り外します。本文: テンプレートごとに明るい背景に暗いテキスト。 |

<a id="critical-anti-patterns-never-do-these"></a>
## 重大なアンチパターン: これらは絶対に行わないでください

これらのエラーは、プレースホルダー形式が出力形式と誤って認識される場合に発生します。これらのパターンを認識することが重要です。

<a id="anti-pattern-1-populating-data-into-placeholder-boxes"></a>
### アンチパターン 1: プレースホルダー ボックスにデータを入力する

**何が起こるか:** テンプレートには、ガイダンス テキストを含む色付きの指示ボックス (黄色、オレンジなど) があります。モデルはガイダンス テキストを実際のデータに置き換えますが、カラー ボックスは保持します。

**間違っている理由:** 色付きのボックスはプレースホルダーです。そこにどのようなコンテンツが含まれるかを示します。出力には異なる書式設定が必要です。通常は白/明るい背景に暗いテキスト、または適切にスタイル設定された図形です。

**認識テスト:** 入力されたスライドにデータ テキストで埋められた大きな色付きの四角形がある場合は、プレースホルダー形式を置き換えるのではなく、コピーしたことになります。

**重要な違い — 2 種類の「プレースホルダー」:**

| 種類 | 見分け方 | 何をすべきか |
|------|-----------------|------------|
| **説明書ボックス** | 明るい色 (黄色、オレンジ)、「ここに X を挿入」などのガイダンス テキスト、色付きの背景に白/明るいテキストが含まれます。 | 図形全体を削除してから、実稼働フォーマットで新しいコンテンツを作成します |
| **レイアウト プレースホルダー** | スライド マスター/レイアウトの一部、テンプレート テーマに一致する中間色、「クリックしてテキストを追加」 | 形状を維持し、テキストの内容のみを置き換えます |

不明な場合は、同じテンプレートの空のスライドにその形状が存在するかどうかを確認してください。レイアウトのプレースホルダーは保持されます。説明書ボックスは通常の形状です。

<a id="anti-pattern-2-text-based-tables"></a>
### アンチパターン 2: テキストベースの「表」

**何が起こるか:** モデルは、実際のテーブル オブジェクトの代わりに区切り文字 (`|`、タブ、スペース) を使用してテーブルのようなコンテンツを作成します。

**間違っている理由:** これは表ではありません。列が正しく整列することはなく、一貫した書式設定ができず、見た目もプロフェッショナルではありません。

**認識テスト:** `|` 文字を入力するか、スペース/タブに依存して列を作成する場合、作成するのはテーブルではなくテキストです。

**必ず確認してください:** テーブルを作成した後、それが実際のテーブル オブジェクトであることを確認してください。検証方法については、[`xml-reference.md`](reference/xml-reference.md#critical-verify-tables-are-actual-table-objects) を参照してください。

<a id="anti-pattern-3-inheriting-placeholder-contrast"></a>
### アンチパターン 3: プレースホルダー コントラストの継承

**何が起こるか:** プレースホルダーは、色付きの背景に明るいテキストを使用します (例: 黄色に白)。モデルはデータを入力しますが、この配色は維持されるため、出力が読みにくくなります。

**間違っている理由:** プレースホルダーの色は、「私を置き換えてください」ということを示すために意図的に区別されています。制作スライドでは通常、本文コンテンツに明るい背景に暗いテキストが使用されます。

**認識テスト:** 入力されたコンテンツの本文領域 (ヘッダーではない) に明るい色の背景に明るい/白いテキストがある場合、プレースホルダーの書式設定が継承されています。

**正しいアプローチ:** 本番用の書式設定を適用します。通常は、本文コンテンツの白または明るい背景に暗いテキスト (#000000 または #333333) を使用します。ヘッダーやアクセント部分にブランドカラーを使用する場合があります。

<a id="summary-placeholder-vs-production"></a>
### 概要: プレースホルダと本番環境

| 要素 | プレースホルダー (入力) | 最終成果物（出力） |
|---------|---------------------|---------------------|
| 説明書ボックス | 色付きの背景、ガイダンステキスト | 削除または再フォーマットされました |
| データ領域 | 「[ここにデータを挿入]」テキスト | きれいなフォーマットの実際のデータ |
| テーブル | テーブルに何を含める必要があるかの説明 | 行/列を含む実際のテーブル オブジェクト |
| 本文 | 色付きの背景に明るいテキスト | 明るい背景に暗い文字 |

**プレースホルダーは、フォーマット方法ではなく、何を作成するかを示します。**

<a id="common-failures"></a>
## よくある失敗

最も重大な障害の詳細な説明については、上記の [重大なアンチパターン](#critical-anti-patterns-never-do-these) を参照してください。

| 失敗 | 解決策 | 参考資料 |
|---------|----------|-----------|
| 非構造化テキストダンプ | 箇条書きに分割する (✓、×、•) | [`formatting-standards.md`](reference/formatting-standards.md#bullet-point-structure) |
| パイプ/タブで区切られた「テーブル」 | 実際のテーブル オブジェクトを作成します。区切り文字のあるテキストはテーブルではありません。 | [`xml-reference.md`](reference/xml-reference.md#table-implementation) |
| テキストと背景のコントラストが低い | すべてのテキスト要素を監査する | — |
| 小さな貼り付けられたグラフ | 領域を埋めるようにサイズを変更し、グラフのみを貼り付けます | [`formatting-standards.md`](reference/formatting-standards.md#proper-sizing-workflow) |
| グラフが貼り付けられたソース データ | コピーする前にチャートオブジェクトのみを選択してください | — |
| プレースホルダーボックスにダンプされたデータ | 色付きの指示ボックスを削除し、適切にフォーマットされた新しいコンテンツを作成します | [アンチパターン](#critical-anti-patterns-never-do-these) |
| 一貫性のない箇条書き | スタイルを一度定義すると、すべてに適用されます | [`formatting-standards.md`](reference/formatting-standards.md#bullet-consistency) |
| ボックス間でフォントが一貫していない | 同レベルボックスの標準化 | [`formatting-standards.md`](reference/formatting-standards.md#font-consistency) |
| コンテンツのオーバーフロー | 明示的なボックスの幅を設定します (脚注: 16:9 の場合は 32.5cm、4:3 の場合は 24cm) | — |
| ロゴがありません | タスク ファイルのロゴを使用します。提供されていない場合は、ユーザーにフラグを立てます | — |
| 残り `[brackets]` | すべてのプレースホルダーを検索して置換します | — |
| テキスト矢印 (→、⟹) | PowerPoint の図形オブジェクトを使用する | [`xml-reference.md`](reference/xml-reference.md#arrow-shapes) |

<a id="error-handling"></a>
## エラー処理

**PDF/画像変換が失敗した場合:**
1. LibreOffice がインストールされていることを確認します: `which soffice`
2. 代替案を試してください: `libreoffice --headless --convert-to pdf presentation.pptx`
3. それでも失敗する場合は、PowerPoint/LibreOffice で手動で開き、エクスポートします。

**ソース データに不整合または競合がある場合:**
1. **優先順位**: タスク ファイルで明示的に提供されたデータを最初に使用します。
2. 他のソース (Web 検索、外部ドキュメント) からのデータを使用する場合は、これをユーザーにフラグを立てます
3. 矛盾がある場合は明示的に文書化する
4. データソースの選択を説明する脚注を追加

**計算がソース予測と一致しない場合:**
1. 計算方法を示す
2. 不一致と考えられる原因 (基準年、方法論の違い) に注意してください。
3. 差に重要性がある場合は両方の値を示します
4. 解決のためにユーザーにフラグを立てる

<a id="table-structure-guidelines"></a>
## テーブル構造のガイドライン

テーブルを作成する場合 (実際のテーブル オブジェクトである必要があります):

**列の配置:**
- テキスト列: 左揃え (ヘッダーとコンテンツ)
- 数値列: 右揃えまたは中央揃え (ヘッダーは内容と一致します)

**ヘッダー行:**
- 太字のテキスト
- 影付きの背景 (テンプレートのブランドカラー)
- 白またはコントラストのあるテキスト

**コンセンサス/合計行:**
- 太字のテキスト
- 上の区切り線
- 独特の背景の陰影

**幅:** 指定されたセクションの幅を完全に埋めます。

XML 実装については、[`xml-reference.md`](reference/xml-reference.md#table-implementation) を参照してください。

<a id="footnote-format"></a>
## 脚注の形式

**形式:**
```
Sources: [Source 1] (Year), [Source 2] (Year).
Notes: (1) [First note]; (2) [Second note].
```

**例:**
```
Sources: Grand View Research (2024), Mordor Intelligence (2024), Markets and Markets (2023).
Notes: (1) Excludes hardware revenue; (2) Includes both B2B and B2C segments.
```

スライド本文内のすべての上付き文字番号 (¹、²、³) には、対応するメモのエントリが必要です。

<a id="logo-placement"></a>
## ロゴの配置

- タスク資料に提供されているロゴ ファイルを使用する
- ロゴが提供されていない場合は、ユーザーに「[ロゴが提供されていません - 会社のロゴを提供してください]」と報告します。
- 位置: 通常は右上、スライド全体で一貫したサイズ、コンテンツと重ならないようにする

<a id="final-quality-checklist"></a>
## 最終品質チェックリスト

入力されたテンプレートを配信する前に、次のことを確認してください。

<a id="data-accuracy"></a>
### データの精度
- [ ] すべての数値は元のソース文書と一致します
- [ ] 計算式に対して検証された計算値 ([`calculation-standards.md`](reference/calculation-standards.md) を参照)
- [ ] 年と期間は正確です
- [ ] 会社名/競合他社名のスペルが正しい
- [ ] 同じ数値は、表示されるすべてのスライドで同一です

<a id="content-mapping"></a>
### コンテンツマッピング
- [ ] すべてのテンプレート セクションに適切なデータが入力される
- [ ] `[bracket]` プレースホルダー テキストは残りません
- [ ] すべての情報源の引用は脚注に含まれています
- [ ] 脚注番号 (¹²³) には対応する注記エントリがあります

<a id="formatting"></a>
### 書式設定
- [ ] すべての背景に対してテキストが読み取れる (十分なコントラスト)
- [ ] テーブルは実際のテーブル オブジェクトです (パイプ/タブ区切りのテキストではありません)。
- [ ] チャート/表は指定された領域を埋めます (サムネイルはありません)
- [ ] 各セクション内で一貫した箇条書きの書式設定
- [ ] フォント サイズは同じレベルのボックス間で一致します
- [ ] スライドの境界を越えるコンテンツはありません
- [ ] データが内部にダンプされたプレースホルダー ボックスは保持されません
- [ ] 最終出力には色付きの指示ボックスがありません

<a id="template-compliance"></a>
### テンプレートのコンプライアンス
- [ ] プレースホルダ指示ボックスが再フォーマットまたは削除されました
- [ ] 書式設定はテンプレートのスタイル (色、フォント) と一致します
- [ ] ロゴが存在し、正しく配置されている
- [ ] 制作書式が適用されました (メイン コンテンツの明るい背景に暗いテキスト)

<a id="final-step"></a>
### 最終ステップ
- [ ] 配布前に Microsoft PowerPoint でユーザー検証を行うことをお勧めします (LibreOffice ではレンダリングが異なる場合があります)
